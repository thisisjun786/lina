# Codex 디자인 언어 적용 기준

2026-09-07 사용자 지시: 디자인 언어를 Codex에서 전면 채택합니다. 색만 맞추는 개편이 아니라 표면·타이포·간격·아이콘·입력·탐색·전환을 하나의 규칙으로 적용합니다. Lina의 에이전트 중심 정보 구조와 사용자용 대화 방식은 그 규칙 안에서 표현합니다.

같은 날 추가된 사용자 피드백에 따라 에이전트 목록은 메신저형 두 줄 행, 모바일은 전체 화면 탐색으로 설계합니다. [목록·모바일 기준](006_agent_list_mobile.md)과 [작업 열 비교](007_sidebar_comparison.md)가 이 부분의 최신 결정입니다. 색·타이포·메뉴·입력창 규칙을 공유하면서 목록의 정보량과 화면 전환은 해당 용도에 맞춥니다.

## 1. 기준과 근거

시각 목표는 Codex의 중립 표면·타이포·입력창·메뉴 규칙이다. 개인 스크린샷은 이 소스의 참조 자산에 포함하지 않는다. 구현 검수에서는 공유 가능한 기준 화면과 버전·viewport·배율을 명시해 재현 가능한 비교를 만든다.

번들 규격과 공개 디자인 코드의 근거는 [조사 기록](000_source_research.md)에 있습니다. 배포 CSS 변수는 후보값이며 선택자·화면 상태·배율을 확인한 최종 적용값과 구분합니다. Apps SDK UI는 공개된 기본 요소의 소스 후보이고, 실제 Codex 화면과 차이가 있으면 선정한 Codex 기준 화면으로 검수합니다.

## 2. 가져올 규칙

| 요소 | Codex 기준으로 맞출 내용 | Lina에서의 적용 |
|---|---|---|
| 표면 | 중립적인 차콜, 영역별 미세한 밝기 차이, 얇은 경계 | sidebar·본문·입력·메뉴·상세 패널을 같은 계층으로 구성 |
| 타이포 | 글자 크기·굵기·줄 간격·텍스트 대비·메타 정보 위계 | 한글 fallback과 확대 설정을 유지하며 같은 밀도로 조정 |
| 간격 | 반복되는 행 높이, 아이콘·텍스트 사이 거리, 그룹 간 여백 | 목록·설정·메뉴에서 같은 규칙 사용 |
| 선택·hover | 중립 회색 선택면, 낮은 강도의 hover, 명확한 focus | 에이전트·하위 작업·메뉴의 상태 체계를 통일 |
| 아이콘 | 크기·선 굵기·정렬·버튼 안쪽 여백 | 탐색·첨부·검색·접기·설정에 일관된 기호 사용 |
| 사이드바 | 중립 표면, 선택·메뉴·상하단 도구·리사이즈 규칙 | 사진·이름·최근 대화의 에이전트 목록과 담당이 명시된 별도 작업 목록 |
| 대화 | 본문 중심축, 읽기 폭, 메시지 사이 여백, 결과물 배치 | 짧은 연속 메시지도 같은 텍스트 위계로 표시 |
| 입력창 | 넓은 곡면, 내부 여백, 보조 조작 위치, 첨부 칩 | 하나의 공통 Composer를 웹과 Electron에서 사용 |
| 메뉴·설정 | 행 중심 옵션, 라벨과 보조 설명, 포커스·선택 표시 | 파일 선택·모델·에이전트 메뉴에 같은 규칙 적용 |
| 상세 패널 | 대화와 연결된 보조 영역, 여닫기·크기 조절 | 결과물·작업 요약·필수 질문을 표시 |
| 움직임 | 짧은 전환, 열림·닫힘과 실제 활동의 구분 | reduced-motion에서도 상태는 유지 |
| 밝은 테마 | 같은 계층의 밝은 표면·중립색·선택 상태 | 흰색 배경만 덧씌우지 않고 모든 상태를 함께 검수 |

기존 Things/Apple 분위기나 파란 선택색을 새로운 Codex 화면의 기본 규칙으로 혼합하지 않습니다. Lina의 이름·로고·캐릭터 사진과 사용자가 정한 대화 형식은 유지합니다. OS 창 조작은 Electron의 실제 기능을 사용하고 웹에 동작 없는 창 버튼을 그리지 않습니다.

## 3. 수치 확정 방식

설계 시작값은 0.25rem 간격 단위, 22px 입력창 곡률, #181818·#212121 중립 표면입니다. 이는 Lina의 검수용 제안값이며 특정 설치 앱의 실제 계산된 스타일을 보증하지 않습니다.

앞선 계획의 48px 헤더·40px 행·832px 대화 폭 등은 Lina를 위해 제안했던 임시값입니다. 공통 Codex 요소는 같은 조건의 측정 결과로 조정합니다. 에이전트 행 40px와 목록 폭 275px는 최신 메신저 목록 설계의 고정값이 아니며, 사진·최근 대화를 수용하는 규격을 별도로 검수합니다. 배포 CSS에서 찾은 숫자만으로 정확히 재현했다고 주장하지 않습니다.

구현 시작 시 색·타이포·간격·곡률·아이콘·메뉴·입력창을 순서대로 대조합니다. 각 항목에 관찰한 상태, 기준 viewport/배율, 실제 또는 추정값, Lina 토큰, 남은 차이를 기록합니다. macOS 스크린샷의 창 외곽·화면 배율을 CSS 픽셀로 그대로 옮기지 않습니다.

웹과 Electron은 같은 디자인 토큰을 가져옵니다. 패키지 분리 전에는 `packages/lina-web/client/tokens.css`가 원본이고, 분리 후 공통 UI 패키지로 한 번만 이동합니다. 테마별 또는 플랫폼별 CSS 복사본을 따로 키우지 않습니다. 모바일은 전체 목록→대화 전환, 하단 탐색, 입력·터치·안전 영역을 별도로 설계하며 같은 상태와 데이터를 사용합니다.

## 4. 대화 요구와의 결합

메신저형 목록과 모바일 탐색에도 Codex의 중립색·대화 타이포·간격을 사용합니다. 각각의 메시지 ID와 경계를 표현하고, 사용자 입력이 끼면 발화 묶음을 분리합니다. 이미 공개한 메시지를 한 덩어리로 재합치거나 수정하지 않습니다.

긴 코드·문서·프롬프트는 온전한 결과물로 표시합니다. 반영 내용과 가정의 짧은 설명은 결과물 바깥의 대화로 이어갑니다. 엔진의 추론·도구 로그를 화면에 표시하는 것은 디자인 채택에 포함되지 않습니다.

## 5. 검수

- 같은 데이터·viewport·배율의 웹과 Electron 화면에서 글자 줄바꿈, 목록 밀도, 본문·입력창 중심축이 일치합니다.
- 빈 화면만이 아니라 긴 대화, 짧은 연속 메시지, 중간 사용자 입력, 첨부, 모델 메뉴, 승인, 오류, 상세 패널을 대조합니다.
- 기본·hover·선택·focus·disabled 상태를 함께 확인합니다. 밝은 테마와 좁은 화면도 같은 규칙을 유지합니다.
- 메신저 목록의 행 구조·폭, 작업 열, 모바일 탐색은 최신 사용자 피드백을 반영한 차이입니다. 그 밖의 시각 규칙이 달라지면 이유를 기록합니다.
- 스크린샷 비교와 함께 리사이즈·뒤로 가기·메뉴 닫기·입력 초점·스크롤 유지·키보드 조작을 실제로 확인합니다.

첫 대조 화면은 에이전트 목록과 기본 대화·입력창입니다. 그다음 메뉴·설정·상세·모바일을 같은 토큰으로 확장합니다. 완료 판단은 Codex와의 시각 차이 및 실제 사용 시나리오를 함께 근거로 삼습니다.
