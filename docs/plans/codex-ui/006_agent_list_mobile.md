# 에이전트 목록과 모바일 탐색

> 구현 전 설계와 당시 코드 조사 기록입니다. 현재 구현·검증·남은 연결은 [구현 기록](010_implementation.md)을 따릅니다.

2026-09-07 추가 피드백 반영. 사용자는 Telegram·Grok Bot·카카오톡처럼 익숙한 에이전트 선택 경험과 모바일 전환을 요청했습니다. Codex의 색·타이포·입력창·메뉴 규칙 안에 메신저형 목록과 탐색을 적용합니다. 이 문서는 기획이며 앱 구현 결과가 아닙니다.

## 1. 변경하는 결정

에이전트 목록은 프로필 사진, 이름, 최근 대화, 읽지 않은 표시를 갖춘 대화 목록입니다. 모든 에이전트에 같은 행 구조를 적용합니다. 선택한 에이전트를 별도 위치로 옮기지 않습니다.

앞선 계획의 한 줄짜리 에이전트 트리, 행 앞 펼침 화살표와 작업 하위 행, 모바일의 사이드바 서랍은 이 계획으로 대체합니다. 작업 목록의 배치는 [사이드바 비교](007_sidebar_comparison.md)를 따릅니다. 각 에이전트의 지속 대화와 작업 소유권은 그대로 이어집니다.

사용자가 정한 것은 메신저 같은 사용감과 모바일을 고려한 구성입니다. 아래 행 크기, 최근 대화 표시 규칙, 하단 탐색, 정렬의 기본값은 이를 구체화한 설계안입니다.

## 2. 에이전트 행

```text
에이전트                       검색  추가

[사진] Lina                     14:32
       그럼 저녁에 이어서 얘기하자.  ●

[사진] Research                 13:18
       자료 두 개를 더 확인했어요.

[사진] Writer                   어제
       확인이 필요한 요청             1
```

이름·내용·시각·상태는 설명용 예시입니다. 실제 목록은 공개된 대화와 작업 기록에서 값을 가져옵니다.

| 부분 | 표시와 조작 |
|---|---|
| 프로필 사진 | 설정한 에이전트 사진. 없으면 이름 기반 대체 표시. 모든 행의 형태·크기 통일 |
| 첫 줄 | 이름과 최근 공개 메시지 시각. 긴 이름은 말줄임, 전체 이름은 접근성 라벨로 제공 |
| 둘째 줄 | 최근 공개 메시지 한 줄. 사용자가 보낸 말은 `나:`로 구분. 코드·파일은 `코드 답변`, `사진`, 파일명 등 실제 콘텐츠 종류로 요약 |
| 읽지 않음 | 작은 점과 텍스트 대비. 짧은 연속 메시지마다 큰 숫자 배지를 늘리지 않음 |
| 확인 요청 | `확인 필요`와 실제 요청 수. 읽지 않음 점과 별개이며 대화를 열었다고 처리하지 않음 |
| 작성 중 초안 | 해당 기기의 초안을 `초안:`으로 표시. 최근 메시지 시각을 초안 수정 시각으로 바꾸지 않음 |
| 실제 작업 중 | 작고 정적인 상태 표시와 접근성 설명. 도구명·토큰·리비전·UUID는 목록에 표시하지 않음 |
| 메뉴 | 데스크톱 우클릭·키보드·더보기, 모바일 길게 누르기와 명시적 더보기. 동일한 프로필·대화 설정으로 연결 |

둘째 줄의 우선순위는 확인 요청 → 미전송 초안 → 최근 대화입니다. 작업 상태를 이유로 행 높이가 계속 달라지지 않게 합니다. 정상 상태에 여러 배지를 겹치지 않습니다. 연결 상태는 실제로 확인된 범위만 표시하며 모든 사진에 상시 초록 점을 붙이지 않습니다.

행 전체를 누르면 대화가 열립니다. 작은 사진이나 펼침 아이콘을 정확히 눌러야 하는 구조를 피합니다. 프로필은 대화 상단의 이름·사진과 더보기에서 엽니다. 행 선택 자체가 키보드를 자동으로 띄우지는 않습니다.

행·사진의 시작값은 데스크톱 64–72px/40px, 모바일 72–80px/48px입니다. 모바일 주요 조작은 48px 정도의 터치 영역을 확보합니다. 이는 Lina의 제안값이며 특정 메신저의 실측값이 아닙니다. 텍스트 확대 때 행은 늘어날 수 있고 이름·상태·버튼이 겹치지 않아야 합니다.

목록은 Codex의 중립 표면 위에 연속된 행으로 놓습니다. 행마다 큰 테두리 카드·배경색·그림자를 붙이지 않습니다. 이름, 미리보기, 시각의 위계를 먼저 검수합니다. 선택은 Codex의 중립색 면으로 표현합니다.

## 3. 정렬과 검색

기존 계획의 안정된 순서를 기본으로 유지합니다. 선택이나 새 발화 때문에 행을 맨 위로 올리지 않습니다. 상단 고정과 최근 대화순은 명시적인 정렬 기능의 후보입니다. 여러 기기에서 서로 다른 자동 정렬을 기본으로 적용하지 않습니다.

최근 대화순을 제공한다면 서버의 마지막 공개 메시지 시각을 사용하고, 초안·작업 심박·스트리밍 토큰으로 순서를 바꾸지 않습니다. 손가락으로 누르는 중이나 목록을 스크롤하는 중에는 재배치를 미룹니다. 이 기능을 구현하기 전에는 작동하지 않는 정렬 메뉴를 넣지 않습니다.

목록 검색은 이름과 역할로 에이전트를 찾습니다. 대화 안의 검색은 해당 대화의 기록을 찾습니다. 입력창과 결과에 검색 범위를 표시합니다. 전체 대화 검색은 서버 검색 계약이 연결됐을 때 확장하며 목록 이름 검색을 전체 대화 검색이라고 부르지 않습니다.

에이전트가 하나일 때도 같은 구조를 유지하고 가짜 추천 에이전트를 채우지 않습니다. 첫 생성, 검색 결과 없음, 목록 불러오기 실패, 이미지 실패를 각각 처리합니다. 요약 로딩 실패를 대화 없음이나 읽음으로 표시하지 않습니다.

## 4. 모바일의 기본 화면

모바일의 기본 진입은 에이전트 목록입니다. 대화·작업의 직접 링크와 앱 재개는 원래 대상을 복원합니다. 좁은 화면에서 목록을 대화 위 서랍에 넣는 방식은 기본 탐색에서 제외합니다.

```text
목록 화면                      대화 화면
┌──────────────────┐           ┌──────────────────┐
│ 에이전트   검색 + │   탭 →    │ ‹  [사진] Lina  ⋯│
│                  │           │                  │
│ 사진 이름  시각  │           │ 대화             │
│      최근 대화 ● │           │                  │
│                  │           │ 확인 요청·상태   │
│ 사진 이름  시각  │           │ 첨부 미리보기    │
│      최근 대화   │           │ 입력창      전송 │
│                  │           └──────────────────┘
│에이전트 작업 설정│              ‹ 목록으로 복귀
└──────────────────┘
```

하단 탐색은 에이전트·작업·설정의 실제 화면으로 연결합니다. 대화 안에서는 하단 탐색을 접어 입력 공간을 확보하고 상단 뒤로 가기로 목록에 돌아갑니다. 작업 화면도 같은 규칙을 사용합니다. 정확한 하단 배치와 행 수는 390px 기준 와이어프레임에서 먼저 대조합니다.

대화에서 돌아오면 목록의 검색어·정렬·스크롤 위치와 마지막 선택을 복원합니다. 다시 대화를 열면 초안·첨부·읽던 위치를 복원합니다. 읽지 않은 메시지가 있더라도 과거 대화를 보고 있던 위치를 강제로 끝으로 옮기지 않습니다.

시트는 첨부 선택·짧은 메뉴 등에 사용합니다. 긴 결과물과 에이전트 설정은 내용 길이에 맞는 화면으로 엽니다. 키보드가 열린 상태의 입력창, 첨부 미리보기, 보내기·중단·필수 확인 요청이 가려지지 않아야 합니다.

브라우저 뒤로 가기와 화면의 뒤로 가기는 같은 탐색 상태를 사용합니다. OS가 키보드를 먼저 닫는 경우 한 번의 입력이 목록 복귀까지 중복 처리되지 않게 합니다. 네이티브 뒤로 가기 제스처와 웹의 수평 제스처를 겹쳐 만들지 않습니다. 길게 누르기·스와이프는 보조 조작이며 모든 핵심 동작은 보이는 버튼으로도 가능합니다.

## 5. 공유 코드와 필요한 데이터

현재 `agents.ts`의 Summary는 프로필·state·dynamics이고, 비활성 에이전트 행의 둘째 줄에는 역할이나 `작업 중`이 들어갑니다. `navigation.ts`는 현재 대화의 마지막 메시지만 `agent-preview`에 표시하고 모바일에서 sidebar DOM을 dialog로 옮깁니다. 모든 에이전트의 최근 대화·읽지 않음과 전체 화면 탐색을 이미 지원하는 것은 아닙니다.

서버 요약에는 agentId, 대화 식별자, 마지막 공개 메시지 ID·순번·시각·종류·안전한 미리보기, 확인 요청 수, 실제 작업 상태, revision을 추가합니다. 미리보기는 저장된 사용자용 메시지에서 추출하며 별도 모델 호출로 발명하지 않습니다. 미공개 후보·추론·도구 로그는 사용하지 않습니다.

읽지 않음은 해당 기기의 마지막으로 본 공개 메시지 순번과 비교합니다. 선택만 했거나 화면이 가려져 있거나 과거 대화를 읽고 있으면 최신 메시지를 읽었다고 기록하지 않습니다. 실제 보인 메시지까지 커서를 전진시키고 재연결로 중복 표시하지 않습니다. 첫 동기화 때 과거 대화 전체를 새 메시지로 처리하는 정책도 별도 검증합니다.

공통 상태는 `screen`, `agentId`, 선택 작업, 원래 목록 위치를 포함합니다. 같은 에이전트 목록 모델을 데스크톱의 목록 패널과 모바일의 전체 화면이 사용합니다. 플랫폼 차이는 배치·뒤로 가기·OS 기능에 두며 대화와 작업을 복제하지 않습니다. [Electron·웹 구조](004_electron_stack.md)를 따릅니다.

## 6. 검수 시나리오

- 1·10·50개 에이전트, 사진 없음·중복 이름·긴 한글 이름을 목록에서 구분할 수 있습니다.
- 확인 요청, 읽지 않음, 초안, 작업 중 상태가 함께 있어도 이름과 필요한 행동을 알아볼 수 있습니다.
- 모바일에서 에이전트 목록 → 대화 → 첨부 → 뒤로 가기 → 다른 에이전트 → 복귀가 자연스럽고 자료가 유지됩니다.
- 320/390/430px, 가로 방향, 키보드 열림, 글자 확대에서도 작은 펼침 아이콘에 의존하지 않습니다.
- 폭을 늘려 데스크톱 배치로 전환해도 선택·초안·검색·읽던 위치와 진행 중 작업은 유지됩니다.
- 전송 중·업로드 중·연속 발화 중에도 탐색과 상태 복구의 기존 보호가 작동합니다.
- 실제 TalkBack/VoiceOver 또는 해당 플랫폼 접근성 도구에서 이름·읽지 않음·확인 요청·메뉴를 구분할 수 있습니다.

정적인 빈 목록뿐 아니라 대화가 쌓인 화면과 엄지로 오가는 흐름을 검수합니다. 사용자용 용어는 `에이전트`로 통일하고 현재 코드에 남은 `비서` 문구도 해당 화면 구현 때 정리합니다.

## 7. 참조 범위

- Telegram의 [2026-02-09 Android 개편 설명](https://telegram.org/blog/crafting-android-design-and-more?setln=en)은 대화·설정·프로필 사이의 하단 탐색을 설명합니다. 이를 참고해 Lina의 실제 기능으로 이동하는 모바일 탐색을 제안했습니다.
- [카카오톡 공식 소개](https://www.kakaocorp.com/page/service/service/KakaoTalk)는 채팅 목록·안읽음 폴더와 프로필 화면 예시를 제공합니다. 대화 상대와 최근 맥락을 알아보는 목록의 참조로 사용하며 소셜 피드나 부가 서비스를 Lina에 추가하는 근거로 쓰지 않습니다.
- Grok Bot은 사용자가 지정한 경험 참조입니다. 이번 확인에서는 특정 버전의 화면·동작을 실측하지 않았으며 세부 UI를 검증된 제품 사실로 기록하지 않습니다.

색·글꼴 위계·메뉴·입력창의 기준은 [Codex 디자인 규칙](005_codex_design_language.md)입니다. 목록의 정보량과 모바일 탐색에 대한 이번 사용자 피드백은 앞선 한 줄 트리 규격보다 우선합니다.
