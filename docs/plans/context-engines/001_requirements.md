# LINA 엔진 완성 — 확정 요구와 미정 항목

2026-09-08 · 세션 01a08149-2fcd-7b83-b427-a104f083df05

상태: I / 인터뷰 산출물. 구현 계획 승인이나 구현 완료 보고가 아니다. 현재 포크의 소스 기준은 0b68b2f이며, 아래 현황은 이 대화에서 읽은 코드와 기록에 한정한다. 새 테스트·실제 모델 호출·설치 상태 검증은 수행하지 않았다.

## 목적과 완료 순서

Honcho의 기억 추론, LCM의 대화 보존, OpenViking의 논리적 자료 공간·업무 기억 원리를 LINA 소유의 경량 엔진으로 흡수한다. 외부 엔진 이름을 숨기는 래퍼나 이름 변경으로 완료 처리하지 않는다. 필요한 출처·라이선스 표기는 유지한다.

합의한 전체 엔진 기능을 실제 실행 경로에서 구현·검증하고, 기능·설정·상태·API 계약을 확정한다. 이를 바탕으로 UI를 기획하고 사용자가 장기 대화를 진행해 체감 품질을 평가한다. 사용자의 장기 실험을 미완성 기능 발견을 위한 대체 검증으로 삼지 않는다. 내부 구현 단계를 나누더라도 전체 범위를 축소하지 않는다.

## 확정된 제품 방향

- 대화 응답은 우선 지정 모델로 완성한다. 대화 모델 자동 라우팅은 후속이다.
- 기억·페르소나·월드·세션 컨텍스트와 업무 기억 처리에는 공통 4단계 모델 라우트를 사용한다. quick/standard/deep/intensive 명칭은 작업용 제안이며, 네 종류의 모델을 요구하지 않는다.
- 기본 모델 조합은 추천하고 사용자가 적용한다. 역할별 무조건 자동 선택은 오선택으로 철회됐다. 에포트·출력 한도·처리 정책은 일반 사용자에게 적절한 기본값을 제공하고 고급 사용자가 변경할 수 있게 한다.
- 고급 설정은 모델과 엔진 내부 정책에 관한 것이다. 별도의 기억 확인·정정 관리 화면을 요구한 것이 아니다. 대화 중 정정·망각 처리는 유지한다.
- 사용자에 대한 추론은 잠정적으로 활용하고 중요한 판단에는 확인한다. 정정되면 갱신한다.
- 에이전트의 핵심 정체성은 유지한다. 취향·관점·관계는 경험에 따라 성장하고 실제 행동에 반영한다.
- 과거의 결정·관심사·고민을 먼저 연결해 탐구한다. 과거 발언으로 사용자를 고정된 유형으로 단정하지 않는다.
- 가벼운 대화는 빠르게, 복잡한 과거 검토는 더 깊게 처리한다. 구체적 시간·비용 한도는 미정이다.
- “잊어줘”의 범위가 불명확하면 기억 제외인지 원문 삭제인지 확인하고, 선택한 범위에서 재학습을 막는다.
- 페르소나와 월드는 순환한다. 성격·관계가 사건 해석과 행동에 영향을 주고 경험이 다시 성격·관계에 반영된다. 사건·비밀의 공개는 성격 공유와 별도로 제어한다.
- 업무 공간은 코드 이외의 파일을 모으는 곳이다. 아이디어, 리서치, 비개발 업무, 파일 정리, 자료와 산출물을 다룬다. 소스 코드는 레포에서 관리한다.
- 업무 공간의 주 사용자는 LLM이다. 사용자는 일상적으로 관리할 필요 없이 필요할 때 폴더 트리 같은 감각으로 탐색한다. Linux 물리 경로를 조직 원칙으로 노출하지 않는다.
- 업무는 사용자의 목적을 위해 수행하는 활동의 상위 개념이며 개발·비개발·단순 검색을 모두 포함한다. 업무라는 표현만으로 코딩, 레포, Codex 작업 또는 별도 실행 세션을 선택하지 않는다. 모든 LINA 에이전트와 Codex가 같은 업무 자료·기억·이어받을 맥락을 사용한다. 업무 경험의 공유가 개인 인격·비밀의 통합이나 직접 경험의 가장을 의미하지 않는다.

## 연결 책임

공유 자료·기억 엔진은 비코드 자료와 활동에서 축적한 지식을 보관·정리·탐색하고, 현재 목적에 필요한 내용을 제공한다. 자료는 특정 업무나 작업 ID 없이도 존재할 수 있다. 작업 배정·실행·완료 판정은 별도 실행/작업 관리 영역의 책임이며, 이 엔진은 그 기록과 근거를 연결할 수 있다. 기록을 연결한다는 이유로 작업 관리자가 되지는 않는다.

업무의 종류(개발·비개발·단순 검색), 실행 방식(현재 대화에서 처리·별도 작업으로 수행), 사용하는 도구는 구분한다. 짧은 검색도 업무지만 반드시 작업 세션이나 영구 기억을 만들 필요는 없다. 개발 업무의 코드 원본은 레포에 두고 관련 비코드 자료·결정 배경·학습한 방법은 공유 공간에서 활용할 수 있다. Codex는 현재 기술적 실행 하네스이자 이 공간을 사용하는 연동 대상이며 업무 자체의 정의가 아니다.

개인 기억은 참여자의 경험을 관리하고, 페르소나는 허용된 성향·관계 변화를 행동으로 반영한다. 월드는 공동 사건과 개인이 알 수 있는 범위를 소유한다. 컨텍스트는 현재 목적과 권한에 맞는 자료만 구성한다. 상태를 여러 엔진에 독립적으로 복제해 수정하지 않는다.

4단계 모델 라우트는 위 처리의 공통 기반이다. 대화 응답의 지정 모델 정책과 분리한다. 연결·인증은 기존 Codex/OpenCodex 경로를 재사용하는 방향이며, 모든 옵션이 프록시에서 동일하게 지원된다고 가정하지 않는다.

## 검증 방법

1. 저장소·정책 단위 검증: 출처, 정정, 중복, 동시 갱신, 데이터 손상과 복구.
2. 실제 실행 경로 검증: UI 없이 API/도구→엔진→저장→다음 소비까지 연결한다. 모의 모델 결과만으로 추론 품질을 주장하지 않는다.
3. 허용된 환경에서 실제 모델로 관찰·재검토·요약·회상을 수행하고 요청 설정, 저장 결과, 후속 입력과 행동을 확인한다. 유료 호출 권한·모델·비용 범위는 별도 확정한다.
4. Codex 작업 생성 없이 LINA 에이전트가 리서치·자료 정리·기획을 기록하고 다른 에이전트가 이어받는 경로를 검증한다. Codex가 같은 업무 공간을 이용하는 연동도 별도로 검증한다.
5. 기능·설정·상태·오류·복구 계약을 확정해 UI 기획에 제공한다.
6. 전체 기능 완성 후 사용자가 장기 대화로 자연스러움·매력·연속성을 평가한다. 기능 검증과 체감 평가는 다른 증거다.

## 미정 사항과 조사 책임

- Honcho/LCM/OpenViking의 기준 버전·라이선스·기능별 흡수/변형/제외 대조표. Honcho와 LCM 일부만 읽었으며 OpenViking 원본 기능 감사는 아직 수행하지 않았다.
- 비코드 파일 가져오기와 참조 연결, 외부 원본 변경·삭제의 의미. 개발 레포 중심으로 제시했던 선택지는 사용자가 채택하지 않았다.
- 물리 저장 방식·임베딩·인덱스·청크 기본값. 일반 파일+SQLite는 제안이며 확정 아님.
- 라우트 명칭, 모델 조합, 상위 등급 선택·실패 대체·출력 한도·처리 주기·비용 기준.
- 기존 데이터 이전·보존 범위와 설치 전환 시점. 기존 Codex/OpenViking 설치 제거는 승인되지 않았다.
- UI의 실제 화면과 엔진별 공개 API 상세. 이 문서는 필요한 계약의 종류만 지정한다.
- 여러 구현 주기에 걸칠 규모다. 계획 진입 시 의존 관계를 포함한 문서 중심 로드맵부터 작성해야 한다. 이 인터뷰 문서는 그 로드맵을 대신하지 않는다.

## 근거 위치

- 현재 대화의 사용자 정정과 합의를 최우선으로 적용한다. 인터뷰 질문/답변은 `.codexclaw/interviews/01a08149-2fcd-7b83-b427-a104f083df05.jsonl`, 누적 상태는 같은 세션의 tracker에 있다. 철회된 자동 모델 선택은 효력이 없다.
- 코드: `packages/lina-runtime/src/models/types.ts`, `context/tree.ts`, `context/external.ts`, `context/memory-query.ts`, `context/companion.ts`, `persona/hooks.ts`, `packages/lina-memory/src/engine/`, `packages/lina-core/src/agents/persona.ts`.
- [Honcho reasoning](https://honcho.dev/docs/v3/documentation/core-concepts/reasoning), [Honcho dreamer source](https://github.com/plastic-labs/honcho/blob/main/src/dreamer/orchestrator.py), [LCM paper](https://papers.voltropy.com/LCM). 2026-09-08에 일부 원문을 확인했으며 전체 기능 감사나 성능 동등성의 증거는 아니다.
- [별도 LCM 구현의 설정](https://github.com/lossless-claude/lcm#configuration)은 청크 설정의 참고 사례다. 사용자가 원래 참고한 구현과 동일하다고 확정하지 않는다.

## 이번 정리의 범위

인터뷰 산출물만 작성했다. 제품 코드 변경·테스트 실행·실제 모델 호출·브랜치 변경·커밋·푸시·PR 변경·머지·배포·기존 설치 변경은 하지 않았다. 현재 워크트리는 detached HEAD이며 구현 시작 전 기준 브랜치와 LIFE 변경의 관계를 다시 확인해야 한다. 저장된 인터뷰 단계는 I이며 계획/구현으로 전환하지 않는다.
