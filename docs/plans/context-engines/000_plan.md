LINA가 개인 기억·페르소나·대화 연속성·공유 비코드 자료 공간을 직접 소유하도록 기존 엔진을 완성한다. 업무는 개발·비개발·단순 검색을 포함하며 Codex 작업 생성과 동의어가 아니다. 전체 기능을 실제 경로에서 검증하고 UI 계약을 확정한 후 사용자가 장기 대화로 체감 품질을 평가한다. [요구사항](001_requirements.md)이 범위 기준이다.

## 실행 계약

- 유형: satisfy-spec, C4(지속 상태·출처·공개 범위·이전 경계). 사용자의 명시적 cxc-loop 요청으로 진행한다.
- 첫 주기: 문서만 작성·감사·검증해 전체 의존 로드맵을 잠근다. 이후 각 단위를 P→A→B→C→D로 구현한다.
- 범위: 현재 checkout의 packages, data 입력 지침, docs 및 필요한 검증 코드. UI는 기능/설정/API 계약을 제공하며 화면 전면 개편은 하지 않는다.
- 권한: 로컬 소스·격리 임시 데이터·공개 소스 읽기. 무제한 사용자 시간/토큰 예산은 지정되지 않았으며 임의 마감이나 축소 기준을 만들지 않는다. 유료 제공자 호출·설치 데이터 변경·푸시·머지·배포는 승인 범위 밖이다.
- 검증: 문서 링크·경로·필드 흐름과 독립 감사; 구현 주기는 red/green, 실제 임시 HTTP/RPC/DB, 중복·재시작·손상·공개 범위 부정 사례. 정확한 명령은 각 단위에서 실행해 기록한다. 아직 실행하지 않은 명령은 통과로 취급하지 않는다.
- 완료: 모든 합의 기능이 실제로 생성→저장→복원→소비되고 UI 계약이 확정됨. 실제 모델 자격 검증은 별도 승인된 범위에서 증거가 필요하며 모의 응답으로 대체 완료하지 않는다.
- 산출물: 이 디렉터리, 현재 세션 .codexclaw evidence와 goalplan. 소스 진실 문서는 docs/ARCHITECTURE.md, docs/PERSONA_CONTEXT.md, docs/CODEX_RUNTIME.md, README.md.
- 제한/에스컬레이션: 독립 LIFE 작업을 덮어쓰지 않는다. 충돌은 계약과 커밋 기준으로 조정한다. 외부 실행 권한이 필요한 검증은 준비된 시나리오/비용 범위와 함께 마지막에 요청한다. 단계 완료와 전체 완료를 구분한다.
