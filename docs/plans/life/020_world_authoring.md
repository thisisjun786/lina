## Contract diff

```ts
// Before: WorldDefinition has one immutable version and flat lore.
interface WorldPack {
  schemaVersion: 1;
  worldId: string;
  version: number;
  background: { authoredText: string; era?: string; environment?: string };
  constraints: WorldConstraint[];
  places: WorldPlace[];
  agentRoles: WorldRole[];
  lore: LoreEntry[];
  predicates: PredicateDefinition[];
  traits: TraitDefinition[];
  rules: DeclarativeRule[];
  eventFamilies: EventFamily[];
  unresolved: AuthoringQuestion[];
}
// Proposed API: draft(input) -> preview(draftId, revision)
// -> activate(draftId, expectedRevision, selectedEffectiveBoundary).
```

A generated draft is not accepted background. User confirmation records exact draft/version/digest and simulation boundary. Partial background is valid authoring input; readiness identifies only missing fields that prevent simulation. Runtime defaults must not silently invent era, participants, economics, relationship axes or time scale. Fixtures and optional examples are explicitly examples.

Risu-inspired supported v1 semantics: primary/secondary exact token keys, always-active entries, priority, placement, bounded recursive activation, declarative comparisons, typed variable reads/assignments, recorded probability, event/fact/relationship/goal effect proposals. Retain source IDs and an import report. Risu import is a documented subset, not card/module compatibility. Unsupported regex/script/Lua/network/model/image/persona-write opcodes never execute; preserve them in a non-executable import report so authors can revise them. Broader compatibility requires a separately versioned parser and tests.

Lore order: apply actor/audience visibility → match keys against allowed perception → evaluate/cache condition, probability and text once → recurse only from successful entries within bounds → budget whole records → place selected records. A discarded lore record cannot set accepted flags. Event prerequisite checks may read authoritative hidden state inside the resolver, but it must not alter the actor's visible candidate metadata before observation. Public narration never uses omniscient lore.

World updates produce a preview of affected locations, rules, actors and pending steps. Reject dangling references and impossible removals; require explicit relocation/effect mapping before activation. Cancel or invalidate stale proposals at the boundary. Existing events/images continue to use their historical definition version. Changing the background never rewrites prior events or persona identity. New agents enter by explicit membership event; retired agents cannot act, while historical relationships remain addressable.

`LifeConfig` separates simulation clock policy, manual/automatic run policy, actor/director model selection, invocation limits, usage policy, publication policy and image/avatar policy. Absent required automatic-run fields mean `not_configured`, not invented defaults. Manual preview can run with fixtures and no paid model. Authoring tools read without approval; mutations use the existing execution/approval mechanism and cannot gain privileges from imported text.

### Pack, draft and rule contracts

`authoring-types.ts` and `authoring-validation.ts` contain the complete version-1 authoring protocol. `WorldPack` references the existing `WorldDefinition` and `LifeDefinition` rather than duplicating their place/trait shapes. It additionally carries background (`authoredText`, nullable era/environment/description), constraints, roles with explicit active/retired membership, typed predicate/variable schema, lore, declarative rules, event families, unresolved questions and non-executable import reports. World IDs and referenced revisions must agree on activation: pack version equals its world-definition version, while LIFE config revision advances from its own previous value. An existing world version 7 with LIFE config revision 1 is not rewritten to make the counters equal. Original authored text remains a separate immutable source in each draft revision; model suggestions cannot silently replace it.

Drafts may have no complete pack yet. `WorldDraft` records ID, world ID, revision, base world/version revisions, authored input, candidate pack or null, suggestion provenance, unresolved items and the last confirmed receipt. Partial background requires no era, participants or time unit to be guessed. Readiness distinguishes missing simulation structure from missing operational configuration. A structurally valid confirmed world can remain `not_configured` for automatic execution.

The interpreter supports finite typed literals/variables, comparisons (`eq`, `ne`, `lt`, `lte`, `gt`, `gte`), Boolean `all`/`any`/`not`, bounded arithmetic and explicitly typed assignment. Compile identifiers and references before evaluation; reject wrong operand types, division by zero, unknown symbols/opcodes and non-finite results. Effect variants are assignment, event candidate, fact proposal, attitude proposal and goal proposal. They remain typed proposals consumed by the author preview now and the 030/040 resolver later; importing or previewing does not run an event or mutate persona. No arbitrary function/loop/property access, regex, template evaluation or executable hook is accepted.

Lore semantics are a documented Lina subset inspired by the pinned Risu research, not a Risu card loader. Token matching uses normalized Unicode word tokens and exact contiguous token phrases, with explicit primary/secondary key combination; authored regex is unsupported. A single evaluation:

1. Select entries and input statements visible to the application-bound actor/recipient. Background source text and private author reports are not actor input.
2. Match always-active or primary/secondary keys. Before an entry can contribute recursive text, evaluate its condition and probability; a false condition or failed draw rejects the entry completely.
3. Evaluate successful entry text once and cache the condition/draw/text result. Add only successful, permitted text to recursion, with an explicit depth/operation bound and visited-entry set. Deterministic draws are keyed by caller seed, evaluation identity and entry/rule ID; hidden or rejected entries cannot shift another visible entry's draw. A rejected A whose body contains B's key must never activate B; test both false condition and probability zero.
4. Sort by declared priority and stable ID; budget whole records using explicit caller limits; preserve declared placement order separately.
5. Stage assignments/effects only for retained entries. Return the selected text, typed effects and random/evaluation receipt. A budget-discarded entry cannot set a flag in the returned accepted-effect proposal.

Cross-entry conditions read the immutable input variable snapshot. Candidate assignments are staged effects, so a later retained entry cannot depend on an assignment from a discarded entry. Within a rule, local expression evaluation has its own bounded typed scope; only retained outward assignments are proposed for persistence, in deterministic priority/ID order. Tests include a dropped setter followed by a condition that would otherwise observe its flag.

Preview and confirmation use the same canonical evaluated receipt; neither advances a scheduler RNG. Actual persistent step-variable changes are committed with the whole LIFE step in 040. This unit proves the interpreter and receipt behavior, not an autonomous loop. Imports preserve source IDs and unsupported raw entries in a bounded report served only to the world author. Supported records are parsed into the same strict pack protocol; unsupported records never become executable interpreter nodes. Report rendering is text/JSON, not HTML/script execution.

### Durable draft/activation API and v3 migration

The public application API on `WorldStore` will expose:

```ts
draftWorld(input): WorldDraft;
worldDraft(draftId): WorldDraft;
worldDrafts(cursor): WorldDraftPage;
worldCatalog(cursor): WorldCatalogPage;
editWorldDraft(draftId, expectedRevision, patch): WorldDraft;
previewWorldDraft(draftId, expectedRevision, previewOptions): WorldDraftPreview;
activateWorldDraft(confirmation): WorldActivationReceipt;
worldPack(worldId, version?): WorldPack;
lifeConfig(worldId): LifeConfig;
setLifeConfig(worldId, expectedRevision, config): LifeConfig;
```

`previewOptions` explicitly binds expected current world revision, simulation boundary, seed, evaluation limits and relocation mapping. `confirmation` binds that same input, draft revision, pack digest, preview digest and durable idempotency key. Activation recomputes/validates the preview against current state inside `BEGIN IMMEDIATE`. Exact retry returns the original receipt, including after later edits; changed material under the same key conflicts. Generation is outside the transaction and must compare the captured draft revision before saving its suggestion. Cancellation/stale generation leaves authored input intact.

Suggestion has its own durable request protocol, because `ModelControl.authoring` offers neither provider idempotency nor result lookup. The request contains a client-persisted request ID, draft/revision, guide-agent ID and expected model-settings revision. `world_authoring_requests` stores that normalized input/digest, scope/grant revision, dispatch status and bounded result/receipt. Creation and the single transition from `prepared` to `dispatched` are serialized in the world DB before calling the existing model port. An active/uncertain request for the same draft revision blocks replacement under a new key. Repeating the same request returns its saved state/result; changed input under the same key conflicts. An in-memory promise map may join waiters but is not the deduplication authority.

An incomplete model suggestion may return `{pack: null, unresolved: AuthoringQuestion[]}` instead of a complete `WorldPack`. At least one question must be blocking; IDs are unique, with at most 64 questions and 4,096 characters per question. This result creates a new draft revision and provenance atomically, preserves the original authored text and creates no world. It survives restart and exact result retry. The runtime supplies provider/model provenance separately from model output. This B contract refinement addresses partial source text that cannot supply an actual agent roster or simulation-time policy; the engine does not guess those values to satisfy a complete-pack schema.

`prepared` proves no dispatch and can resume with the same key. `dispatched` after process loss means `unknown`, never automatic regeneration. Since this provider port cannot look up the result, the author must explicitly resolve/abandon that uncertainty before another attempt for the same draft revision; the record is retained. A model response is strictly validated, and its terminal receipt plus the new draft revision commit atomically. Crash before that commit stays uncertain; crash after commit returns the same stored result without another call. Cancellation after dispatch retains uncertainty unless the outcome is known. A stale/revoked response cannot update the draft. Test concurrent repeated requests, new-key bypass attempts, crash after the dispatch marker, SQL failure during result/draft commit and response loss after commit with a counted fake provider and real reopen. Existing authored input survives all paths.

Schema v3 adds strictly recognized tables: `world_drafts` (draft identity/current revision), `world_draft_versions` (immutable revision JSON/digest), `world_packs` (world/version JSON/digest/effective revision), `world_activations` (confirmation key/digest/draft revision/result), `life_runtime_config` (world/revision typed JSON/digest), `world_authoring_requests` (suggestion state/result above) and `world_author_grants` (grant ID/world/guide-agent/revision/status). Draft edits append a revision then update the head in one transaction; prior raw inputs and suggestions remain recoverable. Pack versions reference the existing world-definition registry and their effective accepted world revision. Drafts/grants can precede world activation and therefore do not require an existing world FK; grants require an existing draft or world with that world ID. Activation receipts link the exact draft version/digest to the pack version and, for updates, the accepted definition-change event. No table stores provider credentials. Audit every new row, version, digest and reference; reject orphan/ambiguous activation state. A recognized v2 file is completely audited with the 010 invariants before any v3 DDL; v1 first follows its existing migration. Injected failure rolls back the complete migration. Unknown future schemas remain rejected without changes. Draft/catalog list APIs require a bounded cursor/page size and return author-management summaries; they are not actor perception tools.

Initial confirmation creates the world, LIFE baseline, pack version and confirmation receipt together. Adopt an existing unpacked world only if its current definition matches the confirmed baseline exactly. A later confirmed version uses an explicit new `definition` variant in the world event protocol; old activity/tick JSON bytes stay unchanged. The new variant retains the common event fields, has no fictional actors/narration/facts, and carries the next authored definition plus explicit relocation mapping. Its accepted world revision increments once, preserving the existing stale-proposal fence. It is a definition event, not a narrated activity or a quiet tick.

For a prepared LIFE world, the corresponding versioned LIFE configuration envelope increments the paired LIFE revision, records the next LIFE definition and migration result, and leaves experiences/claims/beliefs/growth history intact. Normal `acceptLife` cannot submit configuration changes or bypass author confirmation. The config envelope is separately parsed; existing version-1 LIFE commit bytes retain their interpretation. Replay starts with the baseline's original config, selects the effective world/LIFE definitions at each accepted event and verifies the final snapshot. Every registry version must be the original baseline or referenced by exactly one confirmed change; an extra unused version is corruption, not a new initial definition. The mutable world row points to current definition JSON, while original and later definitions remain immutable in the registry. Historical `snapshotAt`/`lifeSnapshotAt` use the same path and preserve old scene text/definition versions for future image inputs.

Changes preserve stable historical IDs. World time unit/initial epoch and existing raw lore facts cannot be reinterpreted; new contextual lore belongs in the new pack. Existing trait/habit/attitude schema identities and numeric baseline meanings cannot be removed/retyped under recorded history. Additive dimensions/members start from explicitly authored initial values; labels and active projection policy may change under confirmation. Locations can change, but occupied removals require a complete explicit relocation. Retired agents stay addressable in historical membership/relations, leave current scene occupancy by explicit mapping and cannot submit new LIFE actions. New members require explicit role/placement. Never create or alter an `AgentProfile` as a side effect.

Activation updates all affected world bindings/policy revisions in the same database transaction, so the 010 native-context fence detects stale references. It invalidates stale proposals using world/config revisions. Scheduler-owned pending-step cancellation and nonempty engine-checkpoint migration are plugged into this same boundary in 030/040; until a compatible migration exists, such a checkpoint is rejected rather than silently reset. No installed ordinary LIFE sharing is enabled here; the 050 memory/identity gate stays in force.

`LifeConfig` separates nullable clock/run policy, director/actor selection, invocation/causal/evaluation limits, usage ceilings, publication audience/policy and image/avatar policy. No inference from the world text fills operational fields. Strict typed parsers and readiness consumers exist in this unit; the later owners enforce those policies when their executors are added. Entire missing groups remain null/`not_configured`; unknown enum values or arbitrary extension blobs are rejected. Configuration changes use optimistic revision and do not start timers or make model calls.

### Runtime path and exact work division

`life/authoring.ts` owns the draft service, optional explicit model suggestion, cancellation and captured-revision checks; `life/config.ts` owns readiness presentation; `life/tools.ts` exports application-bound authoring tools. Read-only draft/preview tools use the existing read allowance; mutations stay behind the actual approval coordinator. An ordinary agent has no world-author authority by default. Only a trusted author-session composition may register these tools, and tool inputs cannot select a different author or gain access from imported text.

Fleet owns one lazy world store/service under its isolated state root and closes it after active authoring requests settle/abort. Management routes under `/api/life` cover draft read/create/edit/suggest/preview/confirm, current/historical pack inspection and config read/update. Read tools are `lina_world_draft_read`, `lina_world_draft_preview` and `lina_life_config_read`; draft create/edit/suggest/confirm and config mutation use distinct non-read tool names and existing approvals. Use strict methods/path/query/body validation, generic errors with no private payload, `409` for revision conflicts and cancellation handling. There is no browser layout or image implementation in this unit. The UI owner receives concrete request/response contracts and examples. Route tests drive the actual Fleet HTTP server with synthetic state/model control and prove the existing origin guard still applies.

Author tools have a concrete isolated execution path in this unit. `POST /api/life/author-sessions` asks the trusted local management API to grant access to one world and one existing guide agent; `AgentFleet.openWorldAuthor()` resolves that persisted grant and calls the injected `createWorldAuthor` factory from `fleet/codex-fleet.ts`. `life/author-session.ts` constructs the real `SessionEngine` session plus `DurableStore`, `DurableRuntime`, `ControlStore`, `ApprovalGate`, `ExecutionCoordinator` and execution hooks under `stateRoot/life/author-sessions/<grantId>/`. It uses the configured guide-agent conversation model, with no fallback model choice, and a pure authored-identity/author-role bootstrap. It does **not** call `startPersistentApp` or construct Companion/Honcho, ordinary `ContextStore`, archive/recall, reflection, workbench or task tools. Only the bound author tools are registered. Ordinary `createApp` registration in `codex-fleet.ts` remains without author tools.

The policy codec gains an explicit version-2 `world-author` policy carrying `authorGrantId` in addition to guide agent/world and policy revisions; version-1 conversation/LIFE policies retain their exact shape. New `author-world` exposure material is allowed only in the author purpose, never actor LIFE or ordinary conversation. This purpose is not an alias for an actor who happens to know the whole world. The trusted current-policy/exposure callbacks read the persisted grant and source references before turns/tools and at the 010 RPC write boundary. Tool/service inputs cannot change grant identity; draft IDs must resolve to the grant's world. Missing, foreign or revoked grants reject before model construction or mutation.

The bound `lina_world_draft_read` tool accepts `{query:"overview", afterId?, limit?}` to discover this world's draft IDs/revisions, confirmed version and current model-settings revision; `{query:"pack", version?}` reads current/historical confirmed packs. Existing `{draftId}` reads remain supported. Overview pages contain at most 32 summaries and never select a foreign world or guide from tool arguments. The author bootstrap teaches this discovery path.

Author session endpoints expose their own durable snapshot/history, input and approval replies; none is forwarded to the ordinary conversation. `POST /api/life/author-sessions/<grantId>/revoke` increments the persisted grant revision and marks it revoked before interrupting/closing the session. In-flight tools and late model results recheck the grant, and world mutations check it inside their SQL transaction. Reopen of an active grant resumes only its isolated Lina/native binding; a revoked grant cannot resume. Regrant creates a new grant/root/context rather than reusing revoked history. Fleet shutdown aborts and closes author sessions before the shared world store; restart does not automatically reopen or submit a model turn. The existing 050 installed ordinary-sharing gate remains unchanged.

Teardown attempts cancellation, runtime closure and native closure independently. A context error after revocation cannot skip native process exit or strand stores/leases. Stores and leases are released only after fulfilled native closure; errors are preserved and unfinished ownership remains held. Factory results transfer cleanup ownership before open admission. A failed late open retains its owner separately from successful-open visibility; shutdown/revoke report unfinished cleanup, and later calls can retry DB disposal without reopening. Native `close()` returns one shared completion, including a sticky failure, so a later no-op cannot falsely certify process exit. Automatic retries of an uncertain native process-group kill are not implemented.

Actual factory/RPC tests must prove the default ordinary path has no author tools, read tools execute in confirm mode, mutations wait for the real approval coordinator, approvals cannot outlive grant revocation, old-scope results do not reach transport, separate history survives reopen, and observer/recall/reflection calls stay zero. Inject engine/model-control doubles at existing interfaces but exercise the real author factory, session adapter and serialized RPC. ### Author native-capability boundary

The author factory cannot inherit the ordinary adapter's `workspace-write`/`on-request` launch. It also rejects any server tool request outside the bound author-tool names. Author mutations still use Lina's separate approval coordinator; rejecting native execution does not auto-approve them. No arbitrary client-supplied permission profile or readiness Boolean enables this path.

The initial supported platform is Linux with an available, qualified Bubblewrap binary. An owned process gets only system runtime files, the exact Codex executable and the grant's dedicated state/work directory; user homes, ordinary Lina state, repository roots, ambient sockets and other grants are not mounted. Existing administrator-managed Codex requirements/configuration must remain available read-only and cannot be bypassed by the wrapper; conflicting requirements make author creation unavailable. Failure to establish this boundary rejects author-session creation; no unwrapped fallback or automatic installation is allowed. Other platforms need their own qualified implementation before enabling this author session. Direct draft-management HTTP operations remain independent of native author-session availability.

Within that process, an explicit named permission profile grants read-only access to its empty author workspace plus minimal system files and disables command networking. Startup and resume select that profile explicitly, with native approval `never`. Disable shell/unified exec/snapshots, apps/plugins/hooks, memory, multi-agent, browser/computer, image/view-image, code-mode, workspace dependencies, tool suggestion, skill search/dependency installation and global goal helpers. Disable web search and request-user-input; supply no external MCP, environment or capability roots. Bundled skill loading and injected skill instructions are off. An empty built-in skill-discovery namespace may remain in a fresh engine's catalog; it must contain no packages/resources, and a resumed engine must not acquire ambient skills. These settings constrain native tools; the approved model transport itself still reaches its configured provider.

Do not infer this restriction from a config file or dynamic-tool list alone. Qualify the exact Codex executable, wrapper/policy template and selected model metadata against a localhost synthetic Responses server before author activation. Repeat after stopping/reopening the native process and resuming the same thread. Admission requires no command/file/image/web/browser/MCP/multi-agent capability, no ambient skill data, rejection of forced command and patch calls, unchanged/unread outside canaries, zero network-trap requests and successful allowed author RPC. Runtime preflight checks the effective profile and empty MCP/skill state on each open/resume; changed binary/policy/model metadata invalidates cached qualification and cannot silently reuse a weaker context. Record the capability-policy digest in the author context policy. The protected store/context roots remain outside the native workspace; this is not a general hostile-host guarantee.
