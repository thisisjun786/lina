# 모이라이 에이전트 코어 설계

상태: 2026-09-11 제품 설계. **모이라이는 경험으로 자기 관점을 형성하고, 그 관점에 따라 행동하는 AI 개인을 유지하는 에이전트 코어다.** 클로토의 전망·계획, 라케시스의 경험·가치, 아트로포스의 의도·연속성을 서로 다른 계산으로 구현하고 하나의 선택으로 연결한다. 선택된 LLM 실행 백엔드는 Senpi이며 라케시스의 학습된 선호에는 MaleCNS v1.0 부분회로를 사용한다.

세 모듈의 메커니즘, 실제 회로 학습, Senpi 제품 통합과 운영 성능은 후속 구현이다. 기존 역할 프롬프트 QA가 새 구조를 구현하거나 효용을 증명한 것은 아니다. 이 문서는 제품 정의·모듈 구조·과학적 근거·평가 방향을, [016 판단·선택·학습·실행 계약](016_neural_preference_contract.md)은 입력·상태·계산·저장·복구의 세부 규칙을 소유한다.

## LINA에서 필요한 이유

LINA는 핵심 정체성을 유지하면서 취향·관점·관계가 경험에 따라 성장하고 실제 행동에 반영되기를 요구한다. 성격이 사건 해석과 선택에 영향을 주고 그 경험이 다시 성격을 바꾸는 순환도 포함한다. 업무 자료를 공유해도 개인 정체성과 비밀은 합치지 않는다. [제품 요구](../context-engines/001_requirements.md#확정된-제품-방향)

이미 [개인 성장 경로](../../../packages/lina-runtime/src/persona/native-growth.ts#L161)가 경험을 해석해 성향 값을 저장한다. 이번 설계는 이 기반에 예측·선호·의도를 계산하는 구조를 연결한다. 어떤 경험이 무엇을 바꿨고 그 변화가 다음 선택에 어떻게 작용했는지 추적하는 것이 목표다.

| 제품 목표 | 확인할 행동 |
| --- | --- |
| 경험과 성장 | 확인된 결과가 다음 예상·선호·접근법을 바꾸고 정정된 경험은 수정 가능 |
| 가치와 선택 | 관심·취향·목표·약속이 충돌할 때 근거를 비교해 제안·수락·보류·대안을 선택 |
| 개인의 연속성 | 회차·모델 세션·재시작이 바뀌어도 정체성·학습·진행 의도가 유지 |

여기서 감정은 행동을 조절하는 내부 상태, 선택권은 허용된 범위의 실행 재량이다. 주관적 느낌이나 자유의지를 완료 기준으로 두지 않는다. 개인 대화·학습·LIFE 행동·재시작·8명 비동기 운영까지 제품 범위에 포함하며 비교 실험을 유일한 산출물로 삼지 않는다.

## 한 개인이 공유하는 기능

| 코어 기능 | 책임 |
| --- | --- |
| 정체성·자기모델 | 이름·기본 성격·능력·한계·관계를 유지하고 현재 자신이 할 수 있는 일을 판단에 제공 |
| 상황 이해 | 현재 원문과 관측에서 사실·가정·예상·불확실성을 구분하고 허용된 세계 상태를 해석 |
| 기억·경험 | 원문·출처·정정과 실제 결과를 저장하고 필요한 경험을 회상 |
| 정서·동기·선호 | 일시적 관심·부담과 오래 남는 취향을 유지하고 주제·활동별 반응을 제공 |
| 목표·의도·약속 | 수락한 목표의 기한·완료·중단 조건과 약속을 유지 |
| 추론·계획·선택 | 후보와 결과를 비교하고 실행할 계획을 결정 |
| 학습·자기점검 | 예상과 실제 결과를 비교해 각 상태 소유자에게 반영 |

이 일곱 기능은 공동 기반이며 일곱 서버·LLM·DB를 요구하지 않는다. 세 판단 모듈도 같은 개인의 기능이다. 기존 Memory·Persona·Resource·World/LIFE 소유권은 [030 도메인 경계](../context-engines/030_moirai_refactor_plan.md)에 따라 재사용한다. 코어의 상황 이해는 그 개인에게 공개된 세계를 해석하며 World의 전체 비밀을 읽지 않는다.

Host 회차 조정층은 필수 입력 전달, snapshot, 계산 순서, 결과 저장, 취소·재시도·복구를 맡는다. 이 조정층에 별도 인격이나 LLM 판단을 추가하지 않는다. [016 상태 소유권](016_neural_preference_contract.md#상태-소유권과-공개-범위)

## 계산 방식이 다른 세 판단 모듈

분리 기준은 **입력 상태·계산·출력·결과 확인 방법**이다. 역할 프롬프트만 바꾸면 실제 경험·예측·약속이 어떤 계산을 바꿨는지 분리하기 어렵다. 별도 인격과 기억을 셋 만드는 안은 한 개인의 정체성과 정정을 중복 관리하게 된다. 하나의 개인 상태를 서로 다른 메커니즘으로 평가하는 구조를 선택한다.

| 모듈 | 주로 읽는 상태 | LLM이 맡는 일 | 코드·계산기가 맡는 일 | 남기는 결과 |
| --- | --- | --- | --- | --- |
| 클로토 `prospect` | 목적·현재 상황·사실 근거·이전 예측 오차 | 전체 행동 후보, 후속 단계와 예상 결과 생성 | 시간·자원·의존 조건 확인, 허용된 관측/검증 결과 연결 | 후보별 예측·가정·비용·확인 방법 |
| 라케시스 `value` | 개인 경험·느린 상태·학습 가중치 | 사건과 활동의 의미를 단서로 변환하고 반응 해석 | 출처 있는 경험 조회, 같은 신경 snapshot의 단서별 반응과 제한된 학습 | 경험 참조·선호 편향·가용성·학습 흔적 |
| 아트로포스 `continuity` | 수락된 목표·약속·정체성·완료/중단 조건 | 모호한 의도와 충돌 해석, 대안·변경 제안 | 상태 전이·기한·자원 충돌 검사, 원래 수락 근거 확인 | 충돌 이유·관련 의도·우선순위와 변경 제안 |

클로토의 예상 비용은 사실과 구분된 예측이다. 각 주장에 출처·단위·가정·검증 상태를 붙이고 실제 결과가 돌아오면 오차를 남긴다. 유효한 문헌이나 도구 receipt 하나로 전체 계획의 정확성을 보장하지 않는다.

라케시스에서는 사실 기억과 선호를 별도 출력으로 유지한다. “지난 활동이 실패했다”는 사실과 “그래서 지금 꺼려진다”는 반응은 연결될 수 있지만 같은 값이 아니다. LLM이 문장으로 취향을 선언한 것을 회로 계산이나 학습 결과로 대체하지 않는다.

아트로포스는 진행 의도를 유지하는 상태 전이를 평가한다. 새로운 관심이 생겨도 수락한 약속은 남는다. 상황이 바뀌면 보류·재개·재협의를 제안할 수 있고 실제 채택·취소는 Host가 원래 수락 근거와 권한을 확인해 저장한다. 아트로포스에 단독 최종 권한은 없다.

필수 원문·정정·현재 권한은 세 모듈 모두 받는다. 처음에는 서로의 출력을 보지 않고 병렬 판단하며 셋 모두 전체 행동 대안을 제안할 수 있다. 서로 다른 결론을 강제로 만들거나 특정 모듈에 필수 사실을 숨기지 않는다. 같은 LLM을 써도 메커니즘을 구분할 수 있으며, 판단 결과가 같다고 분리에 실패한 것도 아니다.

## 모이라이의 종합과 실제 작동 순서

예를 들어 마무리하기로 한 작업 중 새 연구 주제가 생겼다고 하자. 클로토는 새 연구가 줄일 불확실성과 필요한 시간을 예상한다. 라케시스는 축적된 경험과 현재 상태에서 연구 주제에 끌리는 정도를 계산한다. 아트로포스는 지금 전환할 경우 기존 목표와 약속이 어떻게 달라지는지 검사한다. 모이라이는 이 근거를 비교해 가능한 계획을 만들고 Host가 선택과 실행을 확정한다.

```text
현재 사건·원문을 관측하고 개인의 공통 snapshot 고정
    → 주제별 관심 조회로 대안 탐색의 입력 준비
    → 클로토 / 라케시스 / 아트로포스의 독립 판단
    → Moirai prepare: 공통 행동 후보 제안
    → Host 정규화 + 세 모듈의 같은 후보 평가
    → 후보 집합 확정, 기준 정책 p0와 선호 b로 한 번 선택
    → Moirai finalize: 확정된 후보 범위에서 계획 구체화
    → Host 검증·실행 release → 기존 owner가 실행
    → 실제 결과 → 예측 오차 / 선호 학습 / 의도 상태 전이
```

최초 의견은 서로 다른 후보를 다룰 수 있으므로 그대로 평균내거나 투표하지 않는다. 공통 후보별로 전망·가치·연속성 평가를 채우고 출처와 snapshot을 확인해야 비교할 수 있다. 같은 계산은 재사용하고 새 후보의 의미·예측에 LLM이 필요하면 추가 호출을 명시한다. 후보 세대·호출 수·시간 예산과 목록을 닫는 규칙을 두어 평가가 끝없이 새 후보를 만들지 않게 한다.

모이라이는 근거 종류를 구분한 종합안과 계획을 제안한다. Host의 `BaselinePolicy`는 선언된 catalog별 목표·근거·비용·명시적 선호·수락된 의도로 기준 분포를 계산한다. 학습된 선호를 여러 모듈 의견에 반복 등장했다는 이유로 가산하지 않는다. 단위가 다른 확신·흥미·의무 점수를 단순 평균내지도 않는다.

일반 대화는 기본 3판단+1종합 수명에서 원래 대화·완결된 의견·상태·구조화된 평가를 Moirai에 전달한다. 행동은 prepare/finalize를 둔 3+2 골격을 사용하지만 추가 평가까지 다섯 호출에 끝난다고 보장하지 않는다. 내부 지침과 의견은 영어, 최종 답변은 사용자 언어를 따른다. 원문을 자르거나 애플리케이션 출력 토큰 상한을 추가하지 않는다.

관심은 후보 생성 전에도 영향을 주고 최종 후보 평가에서도 읽힌다. 이는 완성된 답변에 랜덤성을 덧붙이는 방식과 구분되는 설계 선택이다. 다만 상태는 새 사실·명령·실행 권한이 아니며, 일반 자연어 답변의 정확한 생성 확률을 보장하지 않는다. 세 판단 원문과 내부 절차는 일반 사용자 대화로 중계하지 않는다.

## 선호가 선택에 들어가는 위치

학습된 선호의 정량 반영은 최종 분포에서 한 번만 수행한다.

```text
p(a) ∝ p0(a) × exp(λ × b(a)),  b(a) ∈ [-1, 1]
```

`p0`는 Host 기준 정책, `b`는 라케시스의 단서별 신경 반응, `λ`는 활동별 허용 재량이다. 기준 정책의 점수 필드에는 신경 선호 값이나 이를 다시 설명한 선호 점수를 넣지 않는다. 후보 생성의 관심 효과와 최종 확률의 선호 효과는 별도 기록으로 구분한다.

가상의 음악·그림 후보가 각각 50%이고 편향이 0.6과 -0.2, λ가 1이라면 최종 선택 확률은 약 69%와 31%다. 실제 회로 측정값이 아닌 계산 예시다. 후보 표현을 중복해 확률을 부풀리거나 조회 순서로 다음 후보의 신경 상태를 바꾸지 않는다.

선택한 후보도 finalize와 Host 검증이 끝나야 실행할 수 있다. 같은 선택을 저장한 뒤 실패했다고 재추첨하지 않는다. 사실·권한·명시적 금지를 확률로 바꾸지 않으며 약속의 변경에는 원래 수락 근거가 필요하다. 선택률과 실제 실행률은 구분한다. [016 행동 확정](016_neural_preference_contract.md#선택과-실행-가능-상태를-분리한다)

## 라케시스에 MaleCNS를 쓰는 이유

일반 순환 신경망이나 문맥 밴딧에도 기억·학습·확률적 선택을 구현할 수 있다. 초파리만 가능한 기능이라고 주장하지 않는다. 이번 선택은 **실측 배선과 알려진 연합학습 구조를 출발점으로 삼는 설계 결정**이다.

버섯체의 KC는 희소한 단서 표현에, MBON은 읽기 출력에, DAN은 구획별 학습 조절에 관여한다. 세포 유형과 연결을 근거로 입력·학습·출력의 역할을 나누면, 무엇을 바꾸었을 때 취향이 달라지는지 회로 단위로 조사할 수 있다. 이 구조가 LINA에서도 효율적인지는 별도 검증이 필요하다. [회로·학습 근거](#s2-회로-선택의-근거)

| 접근 | 설계에서 얻는 것 | 별도로 입증할 것 |
| --- | --- | --- |
| 기존 성향 저장·모델 해석 | 이미 있는 경험·출처·성향 합성 경로 | 새 신경 경로와 같은 경험을 중복 반영하지 않는가 |
| 일반 순환망·문맥 밴딧 | 원하는 상태·보상·선택 문제에 맞춘 학습 모델 | 개인의 취향 유지·수정과 장기 간섭을 어떻게 관리하는가 |
| 초파리 원리 모형 | 희소 표현·구획 학습 등 알려진 원리로 직접 구성 | 실제 배선 없이도 필요한 기능을 얼마나 달성하는가 |
| MaleCNS 기반 부분회로 | 실제 세포·연결에 근거한 구조 제약과 개입 대상 | 그 배선이 단서별 기억·선택·조정 비용에 어떤 기여를 하는가 |

추천하는 주 경로는 MaleCNS 부분회로의 제한된 가소성과 LINA의 명시적 상태 관리다. 일반 모델이 더 좋은 결과를 낼 가능성도 열어 둔다. 같은 입력·기억·학습 신호·조정 예산에서 비교하고, 원래 배선의 기여와 의미 변환기·읽기층의 기여를 따로 보고한다. 모든 일반 모델보다 우월함을 먼저 증명해야 대화와 LIFE 기능을 만들 수 있다는 관문은 두지 않는다.

## 어떤 자료를 가져오는가

사용할 배선 출처는 Google Research가 소개한 MaleCNS v1.0이다. Google·HHMI Janelia와 협력팀이 공개한 수컷 초파리의 중앙뇌·시각엽·복부신경삭 연결 지도다. 발표의 16만 6천 개 이상 뉴런과 1억 2,500만 시냅스 연결은 전체 CNS 규모이며, LINA가 실행할 부분회로의 크기가 아니다. [Google 발표](https://research.google/blog/a-connectomics-milestone-mapping-the-complete-male-fruit-fly-brain/)

공개 자료는 해부학적 배선이다. 완성된 감정 엔진·가소성 규칙·시뮬레이터 체크포인트를 함께 제공하는 모델로 취급하지 않는다. 뇌 영상의 재구성에 쓰인 AI와 LINA의 뉴런 계산기는 역할이 다르다.

| 자료에서 가져올 것 | LINA에서 추가할 것 |
| --- | --- |
| 세포 ID·유형·좌우·영역과 연결 | 사용할 부분회로와 경계 입력·억제 조건 |
| 연결별 접촉 수 | 계산용 가중치 변환·범위·단위 |
| 전달물질 예측 | 전달 부호·불확실성 처리와 동역학 |
| 회로 구조 | 의미 입력, 뉴런 방정식, 읽기층, 개인별 학습 규칙 |

첫 대상은 버섯체 계열의 KC·MBON·DAN과 필요한 입력·억제·피드백이다. 실제 세포 목록과 해시는 추출 산출물로 확정한다. 전체 CNS를 매 순간 실행하지 않아도 개인 학습·대화·선택·복구 기능을 구현할 수 있도록 설계한다. 전체 지도는 회로 경계를 대조하고 후속 감각·행동 경로를 확장할 자료로 유지한다.

FlyWire 성체 암컷이나 hemibrain 연구는 기능과 세포 유형을 대조하는 참고 자료다. 개체가 다른 뉴런 ID·가중치·체크포인트를 합치지 않는다. 암컷 pC1d/e–aIPg 연구를 수컷의 기본 감정 회로로 옮기지 않는다. 제품의 분·시간 단위 지속성은 먼저 명시적 느린 상태로 구현하고, 생물학적 재귀 회로 확대는 별도 프로필로 검증한다.

neuPrint dataset ID, bulk 파일, 필터·해시·입출력·학습 프로필과 라이선스 기록은 [016 데이터와 회로 프로필](016_neural_preference_contract.md#데이터와-회로-프로필)에 모았다.

## 경험이 다음 판단에 남는 방법

실제 결과는 하나의 출처 사건으로 저장하고 각 기능의 소유자에게 전달한다. 클로토는 예측 오차, 라케시스는 선호 학습, 아트로포스는 의도 전이를 반영한다. 소비자별 변경과 receipt를 원자적으로 저장해 재시작이나 프로그램 버전 변경으로 같은 결과가 두 번 적용되지 않게 한다. 내부 의견을 세 개의 독립 경험으로 저장하지 않는다.

신경 학습은 공통 배선 W0를 고정하고 선언된 연결의 개인별 ΔW만 바꾼다. 당시 단서가 남긴 학습 흔적과 확인된 결과·예측을 연결하고, 구획별 학습 규칙을 적용한다. 빠른 상태가 쉬는 상태로 돌아가도 학습 가중치는 유지한다. 늦은 결과는 현재 가중치에 한 번 반영하며 과거 snapshot으로 최근 학습을 덮지 않는다.

피드백 없음은 부정 보상이 아니다. 반복 선택·자기 감정 설명·답변 생성 자체를 성공 보상으로 쓰지 않는다. 같은 성향 dimension을 기존 성장과 신경 학습으로 중복 생성하지 않는다. 신경 가중치는 사실 기억이나 작성된 정체성의 원본을 변경하지 않는다. [016 학습 계약](016_neural_preference_contract.md#경험-학습과-지연된-결과)

## 8명의 비동기 실행과 복구

8명은 개인 정체성 8개이며 내부 판단 모듈 수를 곱해 별도 개인을 만들지 않는다. 공통 배선은 공유하고 개인·공개 범위별 상태·가중치·난수·기록은 분리한다. 비공개 세계가 있으면 실제 상태 수는 8개보다 많다.

Host의 AgentCoreStore가 회차·예측·의도·선택·효과 outbox를 소유하고 신경 저장소는 관측·수치 상태·학습을 맡는다. 사실·대화·세계 원본은 기존 owner에 남는다. 신경 어댑터를 교체해도 코어의 정체성과 선택 기록을 유지한다.

회차 lease로 개인·scope의 순서를 지키고 정정·권한 회수·약속 변경은 즉시 무효화한다. 유효한 관측을 저장한 뒤 행동이 취소돼도 관측을 자동으로 되돌리지 않는다. 출처가 철회된 학습은 재생하거나 격리한다. checkpoint는 기존 owner가 쓰기 중지와 공통 순번을 조정하고 저장소·blob·대기 효과를 하나의 manifest로 묶어 복원한다.

신경 계산 장애에는 명시적 무변조 경로를 둘 수 있다. 필수 판단·근거·권한의 누락에는 이 경로를 쓰지 않는다. 대화는 신경 자료 없이 진행하고 행동은 같은 적격 후보의 기준 정책을 사용하며, 없는 학습 흔적을 만들어 보상하지 않는다. 단일 Python 프로세스의 장애가 여러 개인에게 영향을 줄 수 있어 실제 장애 시험도 필요하다.

## CPU와 GPU의 역할

신경 엔진은 뉴런 상태와 희소 연결을 수치 계산하는 소프트웨어다. LLM 백엔드인 Senpi와는 별도 계산 경로이며, 원격 LLM을 사용하더라도 신경 상태는 로컬에 보존할 수 있다.

처음에는 CPU 부분회로를 추천한다. 정확한 회로·연결 수·관측 단계·단서별 조회 횟수·학습 마스크를 고정한 뒤 지연과 메모리를 측정한다. 8개의 전체 뇌를 항상 실시간으로 돌려야 하는 설계는 아니다. 유휴 개인에게는 선언한 느린 상태 감쇠를 적용하고 필요한 회차만 계산한다.

| 측정 대상 | 확인할 것 |
| --- | --- |
| 계산 | 관측, 활동별 조회, 가소성에 드는 시간 |
| 운영 | IPC, 큐 대기, DB·상태 blob 기록과 복구 |
| 용량 | 공유 그래프, 활성 scope별 상태·가중치·trace, 임시 조회 버퍼 |
| 통합 | LLM 시간과 신경 추가 지연, 취소·재시도·동시 도착 |

p95 100ms·deadline 250ms, 전체 평균 2건/초와 8건 동시 도착은 초기 미측정 목표다. 실제 단서 조회와 학습 비용까지 포함해 다시 산정한다. 이를 LLM 출력이나 추론을 제한하는 기준으로 쓰지 않는다.

CPU가 목표를 충족하지 못하면 동일 프로필과 부하에서 GPU의 실제 RAM/VRAM·처리량·수치 오차를 비교한다. 전체 CNS의 뉴런·시냅스 수나 배열 크기 계산만으로 특정 GPU가 충분하다고 확정하지 않는다.

## 효용을 판정하는 방법

| 확인할 원인 | 통제한 개입과 관찰 |
| --- | --- |
| 전망·계획 계산 | 목표와 선호를 고정하고 외부 근거를 바꿔 클로토의 예측·계획 수정과 실제 예측 오차를 확인 |
| 경험·가치 계산 | 같은 입력·readout에서 상반된 경험 또는 개인 ΔW 교환/차단. 라케시스 평가와 다음 선택 경향이 움직이는지 확인 |
| 의도·연속성 계산 | 같은 경험·예측에서 수락한 약속·기한만 변경. 아트로포스의 충돌 판단·재계획·실행 조건이 바뀌는지 확인 |
| 전체 구조의 기여 | 같은 LLM·원문·기억·총자원의 역할 프롬프트 방식, 전체 구조, 메커니즘 하나씩을 끈 조건 비교 |

모듈 단독 시험에서는 다른 입력을 고정해 원인을 확인하고 통합 시험에서는 그 변화가 후보 생성·선택·결과로 전파되는지 본다. 모든 모듈이 서로 다른 답을 내는 비율을 성능으로 삼지 않는다. 목표 지속·선호 유지/수정·사실 정확도·실제 실행 결과·총비용을 각각 기록한다.

회로는 빠른 상태 초기화·재시작·새 난수 시드 뒤에도 학습 경향이 남는지 검사한다. trace와 결과의 연결을 섞는 조건, 무보상·반대 결과, 외부 readout만 학습하는 조건도 포함한다. 일반 순환망/밴딧·원리 모형·재배선·MaleCNS를 같은 입력·학습 신호·조정 예산으로 비교해 배선의 기여를 분리한다.

후보 표현·중복·순서, 평가 누락·예산 소진, 선호의 이중 가산과 source/약속 변경도 반례에 넣는다. 조정용 경험과 평가용 경험을 분리하고 실패를 누락하지 않는다. 모델의 감정 자기보고나 사후 설명으로 판단·학습 성공을 채점하지 않는다.

## 출처와 검증 범위

### S1. 공개 모델의 범위

배선의 정본은 [Google 발표](https://research.google/blog/a-connectomics-milestone-mapping-the-complete-male-fruit-fly-brain/)와 [Janelia MaleCNS](https://www.janelia.org/project-team/flyem/male-cns-connectome)다. [v1.0 배포일](https://male-cns.janelia.org/release/)은 2026-06-08, Google 발표와 정식 논문 공개는 2026-09-03이다. [공식 다운로드](https://male-cns.janelia.org/download/)에서 annotation·전달물질 예측·연결 그래프를 제공한다. 데이터의 CC-BY 4.0 고지와 변형 기록을 유지하며 실행기 코드의 라이선스와 구분한다.

다른 FlyWire 기반 시뮬레이터는 계산 구현을 참고할 수 있으나 MaleCNS 데이터와 바로 호환되는 체크포인트로 취급하지 않는다. 데이터 공개 자체는 LINA의 감정·학습 기능 검증이 아니다.

### S2. 회로 선택의 근거

[성체 버섯체 연결 연구](https://elifesciences.org/articles/62576)는 KC·MBON·DAN과 피드백 구조를 설명한다. [DAN 유형별 학습 실험](https://elifesciences.org/articles/16135)은 학습 조건·기억 유지·수정 규칙이 구획과 자극 시점에 따라 달라짐을 보여 준다. 이는 제한된 연합학습 회로를 선택하는 근거이며 LINA의 의미 변환이나 인간 취향 대응을 증명하지 않는다.

[암컷 지속 활동 연구](https://elifesciences.org/articles/59502)는 특정 사회 행동 맥락의 근거로만 사용한다. MaleCNS의 기본 감정 회로를 지정하는 증거로 확대하지 않는다.

### S3. 학습 규칙의 범위

[Eligibility traces와 three-factor learning](https://www.frontiersin.org/journals/neural-circuits/articles/10.3389/fncir.2018.00053/full)은 활동 흔적에 이후 조절 신호를 연결하는 일반 틀이다. 이 문서의 제품 시간·결과 신호·제한 학습식은 공학적 설계다. 실제 세포 목록·구획별 부호·학습 상수와 예측기는 회로 프로필에서 검증한다.

### S4. 현재 LINA 연결 지점

기존 코드 대조 기준은 `522101ff99e356b0ea6d27b4ea03ec7e599ee4b3`다.
