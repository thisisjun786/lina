# 초파리 회로를 쓰는 감정·선호·선택 엔진 설계 초안

상태: 2026-09-11 연구·제품 설계 초안. LLM 인지 엔진에 초파리 유래 신경 회로를 연결해, 경험과 현재 상태가 실제 선택을 바꾸는 개인 에이전트를 만든다. 이 문서는 운영 가능한 구현 방향을 제안한다. 신경 시뮬레이터의 Lina 연동, 행동 실험, 하드웨어 측정은 아직 수행하지 않았다.

Moirai는 상황을 이해하고 내부 조언을 평가해 최종 응답을 만든다. 신경 엔진은 에이전트마다 남는 상태와 학습된 선호를 Moirai의 현재 입력으로 제공한다. 행동을 확률로 확정해야 하는 경로에는 별도의 후보·선택 계약을 추가하고, 결과는 다음 선택에 남긴다. 목표는 말투에 감정을 입히는 수준을 넘어, **같은 상황에서도 어제의 경험과 오늘의 상태 때문에 선택 경향이 달라지는 에이전트**다.

선택한 방향은 **초파리 회로를 실제 선택 경로에 넣는, 상태를 보존하는 로컬 서비스**다. 버섯체의 연상학습 구조와 재귀 회로를 출발점으로 삼고, 개인별 가소성·느린 상태·입출력 변환을 함께 설계한다. 부분회로로 시작해도 제품 기능은 감정 상태, 취향 형성, 자율 선택, 복구까지 갖춘다. 비교 실험은 어느 회로와 설정을 쓸지 결정하는 수단이며 프로젝트의 종착점이 아니다.

독자는 이 문서에서 기능 범위, 계산 방식, Lina 연결 지점과 구현 순서를 판단할 수 있다. 아래 수식·계약·성능 예산은 별도 출처가 없는 한 제안이며, 신경과학에서 입증된 인간 감정 모형을 뜻하지 않는다.

PR #10 대조 후 수정: 현재 Moirai의 출력은 후보 JSON이 아닌 사용자 답변이다. 세 모듈의 의견도 추첨할 세 행동이 아니다. 일반 대화의 상태 전달과 명시적인 행동 추첨을 각각 설계하며, ‘LLM 두 번 호출’이라는 설명을 Moirai 전체의 호출 수로 사용하지 않는다. 대조한 리비전과 실제 연결 경로는 [S5](#s5-pr-10의-최신-인지-계약)에 기록했다.

## 사용자가 체감할 변화

음악과 그림을 모두 좋아하던 에이전트가 음악 활동에서 새로운 패턴을 발견했다고 하자. 발견의 결과가 기록되면 음악 관련 입력에 대한 학습된 반응이 바뀐다. 잠시 높아진 탐색 상태도 다음 선택에 영향을 준다. 이후 자유 시간에 음악을 고를 가능성이 커지지만, 그림을 고를 가능성도 남는다. 음악만 반복하면 익숙함이나 포화가 쌓여 다른 활동으로 전환할 수 있다.

이때 역할은 명확하다. LLM이 ‘새 패턴을 발견했다’는 의미를 해석하고 증거를 연결한다. 신경 회로는 그 입력과 이전 상태를 계산한다. 학습 규칙은 실제 결과에 연결된 회로 반응을 갱신한다. 음악과 특정 뉴런 집단의 대응은 우리가 설계한 변환이다. 해당 뉴런에 인간의 음악 취향이 원래 들어 있다고 주장하지 않는다.

| 기능 | 실제로 바뀌는 것 | 확인할 행동 |
| --- | --- | --- |
| 일시적 감정 상태 | 탐색, 주의, 접근·회피, 전환의 강도 | 놀란 뒤 신중해지고 중립 시간이 지나면 완화된다 |
| 장기 선호 | 특정 활동·상대·방법에 대한 학습된 반응 | 다음 날이나 재시작 뒤에도 선택 경향이 남는다 |
| 개별성 | 출발 성향, 경험 이력, 학습 상태가 개인별로 다름 | 시드를 다시 뽑아도 개인 간 경향 차이가 남는다 |
| 선택권 | 허용된 범위에서 제안·수락·보류·대안을 고름 | ‘보류’를 골랐으면 실제로 시작하지 않는다 |
| 자기 설명 | 확정된 선택과 허용된 원인을 언어로 표현 | 설명 때문에 행동을 다시 고르거나 원인을 꾸미지 않는다 |

업무 정확도만 목표로 삼지 않는다. 품질을 유지하면서 선호의 연속성, 상황에 맞는 전환, 구별되는 개별성이 좋아져도 제품 가치가 있다. 주관적 느낌이나 자유의지의 존재는 이 설계의 완료 기준으로 삼지 않는다. 여기서 감정은 행동을 조절하는 내부 상태, 선택권은 사용자와 합의한 범위 안의 실행 재량을 뜻한다.

## LLM과 신경 엔진의 역할

PR #10의 최신 인지 설계는 세 내부 조언과 한 번의 Moirai 종합이다. 세 기능은 하나의 인지 과정 안에서 목적·가능성, 근거·신념, 의도·약속을 검토한다. 에이전트 8명은 개인 정체성 8개이며, 그 안의 인지 기능마다 별도의 성격이나 신경 정체성을 부여하지 않는다. [S5](#s5-pr-10의-최신-인지-계약)

일반 대화에는 다음 순서로 연결한다. 이는 PR #10에 추가할 설계이며 현재 구현된 신경 연결이 아니다.

```text
Host가 원래 대화·허용된 경험·현재 지시를 고정
        ├─ 세 인지 모듈 → 완결된 영어 조언 3개
        └─ 사건 특징 + 이전 신경 상태 → 현재 선호·조절 상태
                         ↓
Moirai: 원래 대화 + 익명 조언 원문 + 허용된 상태 자료
                         ↓
사실·의도·약속과 현재 성향을 함께 판단 → 사용자 답변 하나
                         ↓
실제 결과·정정 → 출처가 있는 경험·신경 상태 갱신
```

핵심 삽입점은 **Moirai가 최종 응답을 생성하기 직전의 입력 조립**이다. 세 모듈이 낸 의견은 완성된 사용자 답변도, 서로 배타적인 세 후보도 아니다. 의견을 원문 그대로 보존하고 `proposals: string[]`와 구분되는 `agentState` 자료를 추가한다. 하나의 의견에 가중치를 곱하거나 의견 일부를 지워서 드리프트를 만들지 않는다. Moirai의 토큰 로짓이나 이미 생성한 문장을 사후 수정할 필요도 없다.

`agentState`는 신경 활동을 읽어 만든 제한된 숫자·분류 자료다. 예를 들어 현재 탐색 성향, 익숙한 활동의 포화, 활동별 학습 선호와 상태 revision을 담는다. 자연어 지시나 새 사실을 넣지 않는다. 숫자는 선택에 참고할 내부 상태이며 외부 사건의 증거·진실 확률·실행 권한이 아니다. 초기에 고정된 사건 변환기가 원래 입력과 허용된 이력에서 특징을 만들면 추가 LLM 호출 없이 기존 3+1 순서를 유지할 수 있다. 별도 의미 해석 LLM을 쓰는 구성에서는 그 호출도 기록한다.

내부 조언·시스템 지침은 영어, 최종 응답은 사용자 언어라는 PR #10의 계약을 유지한다. 신경 자료의 필드 설명도 영어로 고정하되 인용 원문과 식별자는 보존한다. 모듈 이름과 session/cache 식별자는 Host 진단에만 남긴다. 세 조언은 모두 완결돼야 종합하며, 신경 자료를 넣기 위해 자르거나 축약하지 않는다.

이 경로의 최종 선택은 Moirai가 담당한다. 상태를 입력했다고 60%의 확률로 특정 답을 한다는 보장은 없다. 동일한 대화·조언에 상태만 바꿔 의미 있는 선택이 달라지는지 측정해야 한다. Moirai는 사실과 약속을 재검토하는 인지 기능을 유지한다. 신경 상태를 무조건 따르는 문장 작성기로 축소하지 않는다.

허용된 신경 상태는 세 모듈의 다음 판단에도 동일한 snapshot으로 제공할 수 있다. 그러면 현재 관심을 반영한 대안 탐색까지 가능하다. 종합에만 상태를 준 효과와 모든 조언에 상태를 준 효과는 따로 측정하고, 동등한 입력·근거 조건을 유지한다. 어느 경우든 현재 지시·정정·필수 문맥을 빼지 않는다.

실제 행동 확률을 보장할 때는 다음 경로를 추가한다. 이 경로는 일반 대화의 필수 단계가 아니며, LIFE 활동·수락·보류처럼 행동 ID를 실행기에 넘겨야 하는 곳에서 사용한다.

```text
세 인지 조언
    ↓
Moirai 결정 단계: 근거·제약을 검토하고 실행 가능한 후보 집합 제안
    ↓
Host 후보 검증 → 신경 상태에서 후보별 편향 읽기 → 한 번 추출·저장
    ↓
Moirai 최종 단계: 확정한 행동·근거로 사용자 답변 또는 실행 계획 작성
    ↓
Host와 기존 실행 owner가 현재성을 재검사한 뒤 실행
```

Moirai 전체로 세면 성공한 기본 회차는 조언 3회·종합 1회의 4호출이다. 위 행동 계약은 조언 3회·후보 결정 1회·최종 응답 1회의 5호출을 설계 기준으로 삼는다. 필요한 도구 조회·추가 해석·재검토는 별도다. ‘LLM 후보 생성 → 추첨 → 표현’은 이 확장 구간의 설명이지 PR #10의 현재 전체 경로가 아니다. 호출 수를 줄이려고 근거 검토를 생략하거나 조언 출력을 짧게 제한하지 않는다.

후보 집합은 Moirai의 결정 단계가 익명 조언과 원문을 대조해 구성한다. Host는 후보 ID·허용 도구·권한·현재성·확인 가능한 전제조건을 검증한다. 내용의 타당성까지 타입 검사로 증명했다고 보지 않는다. 근거가 부족한 행동은 필요한 확인을 먼저 수행하며, 허용된 재량이 있는 후보 사이에서만 추출한다. 추출 후 새 근거로 선택이 무효가 되면 Moirai는 재검토 사유를 반환하고 Host가 다음 결정을 시작한다. 편향을 따르기 위해 사실을 꾸미거나 몰래 다시 고르지 않는다.

자율성의 범위는 활동별로 정한다. LIFE의 자유 활동에서는 취향이 선택을 크게 움직여도 된다. 맡은 업무에서는 동등하게 타당한 수행 방법, 탐색 순서, 휴식 제안 등에 영향을 준다. 정답, 사실, 권한, 명시한 약속을 난수로 정하지 않는다. 중단·거절·보류 권한이 있는 활동만 그런 후보를 제공한다. 실행 불가능한 후보는 어떤 편향으로도 되살리지 않는다.

## 어떤 초파리 회로를 가져오는가

공개 연결지도는 회로의 배선 출처를 제공한다. 뉴런의 작동 규칙, 배경 자극, 가소성, 입력·출력 의미를 모두 완성해 주지는 않는다. Eon도 내부 상태와 학습·가소성이 상당 부분 빠져 있다고 설명한다. 이 누락을 구현 과제로 받아들이며, 그 모듈을 추가한 뒤에는 기여를 구분해 평가한다. [S1](#s1-공개-모델의-범위)

| 구성 | 채택하는 역할 | 추가로 설계할 부분 |
| --- | --- | --- |
| 버섯체 계열: Kenyon cell, MBON, DAN 및 관련 입력·억제·피드백 | 희소한 입력 표현, 경험과 결과의 연합, 후보별 학습된 매력 | 의미 입력의 부호화, 제한된 가소성, 결과 신호와 시간 배정 |
| 재귀 회로 | 직전 자극과 경쟁 상태가 다음 반응에 남는 동역학 | 회로 경계의 입력, 안정적인 배경 구동, 읽기 집단 |
| 느린 조절 상태 | 제품 시간에서 흥미·부담·포화 등이 지속·완화 | 시간상수, 범위, 회로에 되먹임하는 규칙 |
| 행동별 읽기층 | 회로 활동을 후보마다 다른 편향으로 변환 | 공통 특징 공간과 작은 고정 투영, 이후 검증된 학습 |

성체 버섯체 연결 연구는 KC·MBON·DAN의 연결과 피드백 구조를 제공한다. 이를 학습 회로의 출발 근거로 쓴다. pC1d–aIPg 주변 회로는 자극 후 지속 상태를 조사할 구체적인 후보다. 이 회로 연구는 암컷의 특정 사회·행동 맥락을 다루므로, 곧바로 인간의 호기심 회로나 범용 감정 회로로 부르지 않는다. [S2](#s2-회로-선택의-근거)

초기 데이터는 공개 FlyWire 성체 암컷 v783 계열로 통일한다. 다른 성별·발달 단계·hemibrain 자료의 뉴런 ID를 그대로 합치지 않는다. 비교 논문의 회로를 옮길 때는 세포 유형·개체·좌우·데이터 버전의 대응을 명시한다. 정확한 뉴런 목록은 첫 구현 산출물인 회로 명세로 고정한다. 이 문서는 아직 추출하지 않은 회로의 뉴런 수나 재현 성능을 약속하지 않는다.

회로 명세에는 데이터 버전·해시·출처, 포함 뉴런과 간선, 연결 부호의 근거, 시냅스 수에서 가중치로 변환한 방법, 삭제한 연결, 남긴 경계 구동, 시뮬레이션 상수, 입력·읽기 집단, 학습 가능한 간선 마스크를 담는다. 단순히 특정 영역만 자르면 억제나 외부 입력이 사라질 수 있어, 경계 조건도 모델 일부로 버전관리한다. 해부학적 접촉 수와 계산용 집계 간선 수는 따로 센다.

배선은 공유하는 고정 부분 `W0`와 개인별로 변하는 희소 부분 `ΔWi`로 나눈다. 학습은 지정한 연결에만 허용하고, 부호·가중치 범위·총 변화량을 제한한다. 회로 내부 학습을 포함하는 구성을 제품 목표로 두되, 어떤 연결에서 어떤 규칙을 쓸지는 원문과 재현 결과로 확정한다. 임의의 보상 업데이트를 실제 초파리 가소성의 복제라고 부르지 않는다.

## 한 번의 선택을 계산하는 방법

이 절의 `p0`, `b(a)`, `λ`, `sample`은 앞 절의 **명시적 행동 선택 경로**에 적용한다. 일반 대화에서는 같은 회로의 상태를 Moirai에 투영하지만, 최종 문장의 확률이 아래 식을 따른다고 주장하지 않는다.

LLM은 사건의 의미와 후보의 특징을 정리한다. 입력은 `sourceSnapshotId`, 근거 참조, 새로움, 반복, 노력, 불확실성, 예상 결과, 활동·대상 특징을 포함한다. ‘지금 행복해야 한다’나 ‘음악을 골라라’ 같은 정답 감정·행동을 신경 입력에 숨기지 않는다. 새로움과 반복은 가능한 한 이력에서 계산하고, LLM 추론값은 추론이라는 표시와 신뢰도를 남긴다.

텍스트는 버전이 고정된 의미 변환기로 저차원 특징 `x`와 후보 특징 `φ(a)`로 바꾼다. 활동 이름·후보 순서·모델의 표현이 바뀌어도 같은 의미는 가깝게 매핑해야 한다. 회로가 문장의 의미를 스스로 이해한다고 가정하지 않는다. 입력 변환기 학습은 오프라인에서 수행하고, 온라인 선택 중 변환기 버전을 바꾸지 않는다.

에이전트 `i`의 빠른 신경 상태를 `h`, 느린 상태를 `m`, 개인 성향을 `θ`로 둔다.

```text
u = boundedEncode(x, m, θ)                    # 집단별 입력 전류 또는 발화율
h_next, activity = simulate(W0 + ΔWi, h, u, ξ, K)
z = readPopulationActivity(activity)          # 유한한 창의 집단별 반응
b(a) = tanh(φ(a)ᵀ R z)                       # 후보마다 다른 [-1, 1] 편향
p(a) = p0(a) exp(λ b(a)) / Σc p0(c) exp(λ b(c))
chosen = sample(p, agentDecisionRng)
```

`ξ`는 에이전트별 의사난수다. 초파리 배선은 난수가 퍼지고 억제되며 이전 상태와 상호작용하는 방식을 제약한다. 공개 PyTorch 구현도 자극을 난수로 생성해 희소 연결망과 LIF 뉴런을 진행한다. 이 구현에 있는 시간칸별 Bernoulli 자극을 생체 잡음 통계의 완전한 재현으로 해석하지 않는다. [S3](#s3-실행기와-상태-구조)

`K`는 사건마다 진행할 신경 계산 단계 수다. 시간 간격 `dt`와 함께 회로 프로필에 고정하며, 큐가 밀린다는 이유로 같은 프로필의 `K`를 조용히 줄이지 않는다. 입력이 끊긴 뒤의 지속성을 검사할 때도 정한 신경 시간만큼 계산을 계속한다. 현실·LIFE 시간이 경과한 것과 신경 시간을 진행한 것은 별도 기록이다.

공통 회로는 사건마다 한 번 진행한 뒤, 동일한 `z`에서 모든 후보를 읽는다. 후보를 순서대로 회로에 넣어 먼저 평가한 후보가 다음 후보의 상태를 바꾸게 하지 않는다. 후보별 신경 자극이 필요한 확장에서는 같은 상태에서 분기한 임시 계산을 사용하며, 선택한 분기만 반영하는 규칙을 별도 검증한다. `R`은 작은 투영으로 시작해 회로보다 큰 읽기 모델이 동작을 전부 설명하는 상황을 피한다.

`p0`는 런타임이 정의하는 기준 선택 정책이다. 적절한 후보 사이에서는 균등하게 시작할 수 있고, 이후 약속·품질·명시된 선호를 반영할 수 있다. LLM의 ‘85점’을 성공 확률로 취급하지 않는다. 기존 선호를 `p0`와 신경 입력에 둘 다 쓸 때도 동일 효과를 두 번 가산하지 않도록 항목의 소유권과 경로를 기록한다.

후보 ID는 중복을 금지하고 확정 전에 정렬한다. 후보가 없으면 허용된 보류 경로로, 하나면 그 후보로 결정한다. 모든 `p0(a)`는 유한한 비음수이며, 후보가 있으면 최소 하나의 양수 질량을 요구한다. 이 조건을 못 맞추면 정책 오류로 중지하고 조용히 균등 분포로 바꾸지 않는다. 제외한 후보는 확률 0으로 유지한다. 계산은 안정적인 log-space 정규화와 유한값 검사를 사용한다. 난수를 변형해서 원하는 결과를 만드는 대신, 후보별 편향을 확률에 적용한 뒤 독립된 선택 난수로 추출한다.

`λ`는 활동의 재량과 품질 조건에 맞춘다. 모든 선택을 50:50에서 55:45 정도만 바꾸는 것으로 제한하지 않는다. `b∈[-1,1]`이면 두 후보의 상대 선택확률 비율은 최대 `exp(2λ)`배 변한다. 동등한 두 후보의 산술 예시는 다음과 같다. 이 값은 효과의 크기를 설명할 뿐, 최적 설정을 입증하지 않는다.

| λ | 가능한 최대 기울기 | 설계에서의 용도 예시 |
| --- | --- | --- |
| 0 | 50:50 | 변조를 끈 상태와 장애 시 기준 정책 |
| 0.1 | 약 55:45 | 업무 방법에 약한 편향 |
| 0.5 | 약 73:27 | 재량이 큰 활동에서 분명한 선호 |
| 1.0 | 약 88:12 | 자유 활동의 강한 취향을 시험하는 설정 |

품질이 떨어지는 후보를 크게 기울여 선택하지 않도록, 후보 집합은 먼저 최소 조건과 허용 가능한 품질 차이로 제한한다. 자유 활동의 높은 `λ`를 업무에 그대로 쓰지 않는다. 학습된 선호는 기준 정책에도 반영할 수 있으므로, 순간 변조의 최대 크기와 장기 선호의 크기는 다른 설정이다.

선택 결과는 후보 ID·후보 집합 해시·확률·상태 버전과 함께 확정한다. Moirai의 최종 단계는 선택된 후보의 계획과 표현을 맡되 근거·의도 충돌을 계속 검사한다. 더 나은 근거가 생기거나 후보가 무효가 되면 이전 선택을 취소하고 새 결정으로 연결한다. 몰래 다른 후보를 실행하거나 실패할 때까지 다시 추첨하지 않는다.

## 경험이 취향으로 남는 방법

세 시간 규모를 분리한다. 밀리초 단위 신경 상태 `h`는 회로 반응과 단기 경쟁을 담는다. 분·시간 단위 제품 상태 `m`은 기분처럼 서서히 완화되는 조절값이다. 반복 경험에서 형성된 `ΔWi`와 선호 기록은 재시작을 넘어 유지한다. 이들 중 어느 상태를 바꿔서 행동이 달라졌는지 확인할 수 있어야 한다.

느린 상태는 다음과 같은 공학 모형으로 시작한다.

```text
m_pre  = baseline + (m_previous - baseline) * exp(-ΔproductTime / τ)
m_post = clip(m_pre + G(z, observedOutcome), allowedRange)
```

`G`와 `τ`는 제품이 정한 규칙이다. 회로 출력을 일부 사용하더라도 시간 단위 지속성의 공로를 전부 초파리 회로에 돌리지 않는다. 개인 공통 상태는 현실 경과 시간, 세계 전용 상태는 해당 LIFE 시간을 사용하며 각 상태에 `scopeId`, `clockId`, 마지막 처리 시간을 고정한다. 두 시계의 차이를 같은 변수에 더하지 않는다. 시간 역행은 버전 오류로 다루고 같은 구간을 두 번 감쇠하지 않는다. 회로가 유휴 중 멈췄다면 ‘저장된 상태’이며 그동안 연속 발화한 것으로 기록하지 않는다.

유휴 복귀 규칙도 프로필에 포함한다. 짧은 유휴는 사건 시간 방식으로 `h`를 이어가고, 해당 시계의 `idleGapLimit`을 넘으면 빠른 전위·발화·지연 버퍼를 휴지 상태로 초기화한다. 느린 `m`은 실제 경과분만 감쇠하고 장기 학습 가중치는 유지한다. 결과 대기 중인 학습 흔적은 원래 결정의 범위·시계로 만료를 판정한다. 이 초기화와 만료는 새 상태 전이로 기록하며 재시작 자체를 초기화 사유로 삼지 않는다. 프로필은 시간 단위·한계값을 반드시 선언한다. 생물학적 지속성 실험은 이 제품 복귀 규칙과 별도로 연속 시뮬레이션한다.

결과 학습에는 선택 시 활성화된 입력·연결의 흔적을 저장한다. 결과가 늦게 오면 `decisionId`로 당시 흔적을 찾아 갱신한다. 실행 실패, 사용자 거절, 피드백 미수신은 서로 다른 사건이다. 피드백이 없다는 이유만으로 부정 보상을 주지 않는다.

```text
δ = trustedOutcomeValue - predictedOutcomeValue
ΔWi_next = projectToAllowedSynapses(ΔWi + η * δ * eligibilityTrace)
```

이 식은 학습 계약의 골격이다. 특정 DAN 집단에 어떤 신호를 주며 KC–MBON 연결이 어느 방향으로 바뀌는지는 회로별 규칙으로 구체화한다. 부호를 무시한 전뇌 공통 Hebbian 업데이트나 모든 연결의 온라인 학습으로 시작하지 않는다. 최초 연결 시 제한된 읽기층 학습도 지원하되, 회로 내부 학습과 외부 읽기층 학습의 결과를 따로 기록한다.

보상은 하나의 ‘좋음’ 점수에 모두 숨기지 않는다. 업무 결과의 확인 가능성, 사용자의 명시적 평가, 자유 활동의 발견·익숙함·포화, 세계 안의 결과를 구분해 출처와 가중치를 남긴다. 허구 사건이 실제 업무 성공의 증거가 되거나, 에이전트의 ‘즐거웠다’는 말이 자기 보상을 자동 생성하지 않게 한다. 반복해서 같은 활동을 골랐다는 사실만으로 그 활동의 보상을 올리지 않는다.

장기 학습 상태는 에이전트별로 보존한다. 서로 다른 초기 감도는 설계한 성향 차이, 서로 다른 경험의 학습 결과는 형성된 취향, 시드 차이는 무작위 경로로 구분한다. 작성자가 정한 정체성이나 사용자의 명시적 지시를 학습 보상으로 덮어쓰지 않는다. 경험의 출처가 철회되면 해당 학습 epoch의 체크포인트부터 유효 이력으로 재생하거나 영향을 받는 학습 상태를 격리한다. 일반적인 가중치 업데이트가 정확히 역산된다고 가정하지 않는다.

5호출 행동 모드는 Host 기록에서 `moirai_prepare`와 `moirai_finalize`를 구분하는 별도 프로토콜로 둔다. 현재 4역할 검사에 다섯 번째 요청을 숨기거나 기존 capture의 6회 차단선을 정상 추가 호출의 허가로 해석하지 않는다. 모드별 예상 요청·실패·취소·재시도·usage를 검증하면서 기존 3+1 비교는 그대로 보존한다. 예전 Codex QA의 단일 `candidate`와 제한된 `alternatives`도 이 프로토콜과 다르며, 최신 영어 조언에 그 JSON 출력을 강제하지 않는다.

제안하는 내부 포트 이름은 `NeuralPreferencePort`다. 기존 이름의 API가 구현돼 있다는 뜻은 아니다. 의미 입력 준비는 인지 owner, 권한과 최종 효과는 기존 커널·Host, 신경 상태와 학습은 신경 서비스가 맡는다. 신경 서비스는 Host 측 저장·선택 담당자와 Python 계산기로 구성한다. LIFE 경험·관계·페르소나 원본을 신경 서비스 안에 복제하지 않는다. 같은 수치가 여러 저장소에서 독립적으로 수정되는 두 번째 성격 시스템을 만들지 않는다.

| 제안 계약 | 필수 정보와 반환 |
| --- | --- |

| `prepareDecision` | agentId, scopeId/clockId, eventId/sequence, source·policy·state revision, 후보와 특징·해시, 시간·예산, 모델 명세. 편향·진단·다음 상태 참조를 준비한다 |
| `commitDecision` | decisionId, 예상 이전 revision, 고정된 후보·정책·확률·준비 상태 해시, source/policy/binding generation. Host가 현재성을 검사하고 로컬 추출로 행동 ID를 확정한다. 동일 요청은 같은 결과를 반환한다 |
| `observeOutcome` | outcomeId, decisionId, 실행 영수증, 출처·유형·평가 확실성, 현재 source/policy/binding generation. 근거가 유효할 때만 한 번 학습한다 |
| `projectState` | 목적·대상·공개 범위에 맞춘 상태 요약. 원시 경험·비밀·회로 전체를 대화에 넣지 않는다 |
| `checkpoint / restore` | 회로·변환기·학습 규칙·시간·난수 버전과 상태를 함께 보존한다 |

일반 대화와 LIFE는 같은 개인 정체성과 허용된 성장 상태를 참조하되, 세계별 사건과 학습 출처를 섞지 않는다. 업무·LIFE 입력은 각각 출처가 있는 stream으로 들어오고 공통 상태에 반영 가능한 필드만 승격한다. 세계 간 학습 전이는 명시적인 계약으로 둔다. 공개 상태의 숫자도 비밀을 추론하게 할 수 있으므로, 원문을 제거했다는 이유만으로 공개 가능하다고 판정하지 않는다.

개인 공통 상태는 공개를 허용한 성장·결과만 입력받는다. 비밀 경험을 쓰는 세계 전용 계산은 별도 `scopeId`의 신경 상태·학습 파라미터로 격리한다. 일반 대화는 그 원시 상태를 읽지 않고 기존 공개 정책이 허용한 성장만 출처가 있는 승격 사건으로 받는다. 하나의 성장 사건을 원본 stream과 승격 stream에서 두 번 학습하지 않는다. 실제 상주 상태 수는 8개의 개인 공통 상태에 활성화한 세계 전용 상태 수를 더해 산정한다.

신경 계산과 상태 준비는 두 경로가 공유한다. 일반 대화는 상태를 한 번 확정한 뒤 그 revision을 종합 입력에 고정하며, 실패한 LLM 호출을 재시도할 때 동일 자료를 재사용한다. 행동 추출 모드는 같은 회차에서 준비한 `z`·상태 참조를 후보별 읽기에 재사용한다. 후보가 늦게 생겼다는 이유로 신경 시간을 다시 진행하거나 같은 사건을 중복 학습하지 않는다. `observeOutcome`은 대화의 회차 ID 또는 행동 decisionId 중 하나를 출처 유형과 함께 참조한다. 생성한 답변은 대화 출력의 증거이며 외부 행동 완료의 증거가 아니다.

## 8명의 비동기 실행과 복구

상주 신경 계산 프로세스 하나가 불변 배선·코드·읽기 설정을 공유하고, 8개의 개인 상태를 따로 관리한다. 각 상태는 신경 버퍼, 느린 상태, 희소 학습 가중치, 학습 흔적, 난수 카운터, 마지막 처리 순번을 가진다. 에이전트마다 Python 프로세스와 전체 배선을 복제할 필요는 없다.

한 에이전트의 여러 채널·업무·LIFE 사건은 단일 상태 writer가 순서대로 적용한다. 서로 다른 에이전트의 요청은 동시에 받을 수 있다. 짧은 대기 구간에서 준비된 요청만 작은 배치로 묶으며, 늦은 에이전트를 기다려 8명 전체를 멈추지 않는다. 인지 LLM 호출 한도와 신경 서비스의 처리량은 별도 예산이다.

Host 측 `NeuralPreferenceStore`를 신규 `state/neural-preferences.sqlite`의 단일 writer로 제안한다. `(agentId, scopeId)`별 증가 순번·상태 참조·결정·outcome inbox·효과 outbox를 이 DB에 둔다. Python은 전달받은 불변 상태로 계산하고 다음 상태를 반환하며 DB나 WorldStore를 직접 수정하지 않는다. 최종 선택 난수는 Host가 소유하고 고정된 분포에서 행동 ID를 산출한다. LLM이나 Python이 보낸 임의 행동 ID를 검증 없이 받아들이지 않는다.

한 세계의 사건 확정과 여러 개인의 계산 병렬성도 구분한다. 동일 세계를 바꾸는 결과는 현재 세계 revision과 lease를 확인해 순서대로 확정한다. 두 사람의 상호작용에서 상대의 수락은 상대 개인 상태로 별도 선택하고, 한쪽 선호가 양쪽의 의사를 대신하지 않는다. 여러 개인의 상태를 갱신하는 사건에는 공통 eventId와 확정 순서를 보존한다. 현재의 foreground 작업 제외 정책은 별도 변경 없이 유지한다.

배치 순서가 개인차를 만들지 않도록 난수는 `(agentId, scopeId, eventSequence, streamKind, counter)`로 구분한다. 자극 잡음과 최종 선택 난수도 분리한다. 같은 에이전트의 사건 순서가 유지되면 다른 7명의 도착 순서나 배치 크기를 바꿔도 같은 결과를 재현해야 한다. GPU 수치 연산 차이는 별도 허용오차로 다루고, 이미 확정한 행동은 재계산 대신 저장된 결과로 복원한다.

처리 흐름은 다음 순서를 따른다.

1. 사건 ID와 입력 해시를 기록하고 상태 revision으로 준비 작업을 예약한다. 진행 중인 동일 사건은 이어서 확인하며 다시 추첨하지 않는다.
2. 작업 복사본에서 계산한다. 다음 상태 blob을 원자적으로 저장하고 해시를 검증한 뒤, 결정·난수 진행량·상태 참조·실행 intent를 하나의 로컬 트랜잭션으로 확정한다.
3. 기존 실행 owner가 신경 DB의 outbox에서 decisionId가 붙은 intent를 소비한다. LIFE는 step에 신경 결정 참조를 저장하고 기존 prepare/reconcile로 중복 소비를 확인한다. 결과는 신경 DB의 outcome inbox로 돌려준다. 서로 다른 저장소에 걸친 단일 트랜잭션을 가정하지 않는다.
4. 실행 영수증이 도착하면 해당 decisionId에 결과를 붙이고 학습을 한 번 적용한다. 결과 확인이 안 된 외부 효과는 확인 대기 상태로 유지한다.

Host는 결정 확정 직전과 실제 효과 실행 직전에 현재 source·policy·binding generation과 후보 해시를 다시 확인한다. 현재성 검사와 확정은 Host의 해당 상태 직렬화 경계에 놓는다. 준비 후 도착한 정정·권한 회수는 이전 후보와 준비 결과를 무효화하며, 무효 작업은 신경 상태·선택 난수·가중치를 진행하지 않는다. 결과 학습도 현재 유효한 근거와 학습 정책을 확인한다. 확정한 결정의 감사 기록은 보존하되, 그 기록을 현재 실행 권한으로 재사용하지 않는다. 전송 시간 초과와 근거 무효화는 구분하며, 후자에는 `p0` 저하 경로를 적용하지 않는다.

재시작은 완결된 상태 참조부터 복구한다. 준비 상태만 남은 작업, 결정은 확정됐지만 아직 실행하지 않은 작업, 실행 결과가 불명인 작업을 구분한다. 모델 버전이 다른 체크포인트를 조용히 초기화하지 않는다. 마이그레이션이 없으면 기존 버전으로 복구하거나 신경 변조를 중지하고 원래 상태를 보존한다.

신경 서비스가 시간 초과·NaN·발화 폭주·지속 포화에 빠지면 해당 준비 결과를 폐기하고, 같은 결정 요청에 명시적으로 `p0`를 사용하는 저하 경로를 기록한다. 기준 정책으로 이미 확정한 결정에 늦은 신경 결과를 덧붙이지 않는다. 아직 확정되지 않은 장애 시도의 상태·난수 진행량은 활성 상태에 반영하지 않는다. 회로 출력을 `tanh`로 제한해도 내부 폭주를 정상으로 보지 않는다.

연속 장애는 해당 회로의 신규 계산을 격리한다. 다른 에이전트와 일반 대화는 기존 경로로 계속 작동한다. 재시도 횟수, 큐 길이, 상태 저장 공간, 진단용 발화 기록을 제한한다. 원시 발화 전체는 항상 저장하지 않고, 평소에는 집단 요약과 재현에 필요한 입력·버전·선택 영수증을 보존한다.

## CPU와 GPU의 역할

제품의 첫 실행 구성은 **Python 상주 프로세스의 CPU 부분회로**다. Lina/Bun은 타입이 있는 로컬 IPC로 호출한다. 참고 방정식과 원본 재현에는 Shiu의 Brian2 구현을 쓰고, 반복 요청에 필요한 상태 보존·선택·학습은 Lina 계약으로 추가한다. 원본은 MIT, Eon의 현재 실행기 저장소는 GPL-2.0-or-later로 표시돼 있으므로 소스를 가져올 때 파일별 출처와 고지를 확인한다. 이 PR은 코드를 가져오거나 두 라이선스를 재해석하지 않는다. [S4](#s4-원본-구현과-배포-검토)

GPU 경로는 같은 입출력·상태 계약의 가속 실행기로 설계한다. 부분회로가 CPU 예산을 초과하거나 회로를 확대할 때 PyTorch/GeNN 계열을 검토한다. 매 요청마다 컴파일·초기화하는 벤치마크 실행기를 제품 서비스로 그대로 호출하지 않는다. 준비 비용, 신경 계산, 큐 대기, 상태 저장, LLM 시간을 따로 측정한다.

초기 구현 목표 예산은 8명 전체에서 신경 서비스의 **추가 지연 p95 100ms, deadline 250ms**, 합계 평균 2건/초와 8건 동시 도착의 짧은 집중 부하다. 이는 연구용 목표치이며 성능 실측이나 지원 사양이 아니다. 이 예산을 Moirai LLM의 출력·추론 시간 제한으로 전용하지 않는다. PR #10의 인지 요청은 애플리케이션 출력 토큰 상한을 두지 않고, 자원 증가만으로 접근을 기각하지 않는다. 자유 활동의 신경 계산은 더 긴 프로필 예산을 허용할 수 있다. 목표를 못 맞추면 신경 계산 창·회로 크기·배치·백엔드를 조정하고, 측정한 품질과 지연을 함께 제시한다.

메모리는 대략 다음 항목으로 구성된다.

```text
공유 희소 배선 O(E) + 개인별 신경 상태 O(B × N × D)
                  + 개인별 학습 O(B × P) + 입력·임시 배열·기록
```

`N`은 뉴런 수, `E`는 계산 간선 수, `B`는 상주하는 개인·범위별 상태 수, `D`는 지연·상태 깊이, `P`는 상태별 가소 연결과 학습 흔적의 크기다. 공유 배선만 보고 학습 상태까지 무료라고 계산하지 않는다. 전뇌 가중치를 개인마다 전부 학습하면 이 비용 구조가 바뀐다.

크기 감각을 위한 가정으로 `N=10,000`, `B=8`, float32, 지연 버퍼 19칸과 뉴런 상태 4개면 주요 신경 배열만 약 7.02MiB다. `E=500,000`인 CSR 배선을 64비트 인덱스·32비트 가중치로 저장하면 약 5.80MiB다. 합계 약 12.82MiB는 학습·프레임워크·임시 버퍼를 뺀 배열 산술이다. 실제 RAM/VRAM이나 이 회로의 필요 크기가 아니다.

기존 공개 전뇌 타이밍은 지속 개인 상태·학습·서비스 지연을 측정한 자료가 아니다. 따라서 ‘8명에는 16~24GB GPU가 필요하다’는 앞선 추정을 요구 사양으로 쓰지 않는다. CPU 상주 실행을 측정한 뒤, 동일한 회로·부하의 GPU 최대 할당량·예약량, 처리량, p95와 상태 동등성을 확인해 지원 장비를 정한다. 외부 LLM을 쓰는 구성에서 신경 엔진 때문에 로컬 LLM 가중치 메모리까지 계산하지 않는다. [S3](#s3-실행기와-상태-구조)

## 구현 순서와 완료 기준

각 단계는 실제 기능을 남긴다. 첫 비교에서 모든 가설의 우위를 증명해야만 다음 기능을 설계하는 방식으로 진행하지 않는다. 회로의 안전한 작동·상태 복구는 연결 조건이며, 특정 배선의 우월성은 별도 연구 결과다.

| 단계 | 구현 산출물 | 완료를 판단할 증거 |
| --- | --- | --- |
| 1. 신경 상태 서비스와 Moirai 종합 연결 | 고정된 회로 명세, CPU 실행기, 특징 변환·상태 투영·후보 읽기, 지속 상태·결정 영수증 | 같은 대화·완결된 조언에서 신경 상태 변경이 선택 경향에 미치는 효과, 원문·익명·언어 계약, 재시작·로컬 부하 |
| 2. 명시적 행동 선택과 LIFE 연결 | Moirai 후보 결정·최종 응답 계약, Host 확률 추출, LIFE intention·target·실행 owner 연결 | 후보 순서 불변, 행동 ID 일치, 무효화·보류·대안의 실제 반영, 중복 선택·효과 없음 |
| 3. 감정 상태와 경험 학습 | 제품 시간 감쇠, 결과 연결, 제한된 회로 가소성·개인 체크포인트 | 상반된 경험의 취향 분화, 무보상 대조, 포화·재학습·정정, 재시작 뒤 경향 유지 |
| 4. 일반 대화·업무와 공유 성장 | 허용된 관심 상태 투영, 후보 생성의 관심 반영, 업무 재량 연결 | 필수 현재 입력 유지, 같은 선호의 지속성, 비밀·세계·실제 업무 출처 분리 |
| 5. 8명 운영과 회로 확장 | 큐·배치·장애 격리·설치·업데이트, 필요 시 GPU와 넓은 회로 | 혼합 부하, 역순 결과, 취소·종료 중 복구, 자원 예산, 설치본 실제 흐름 |

단계 1에서도 실제 신경 계산이 Moirai 입력을 바꾸며, 상태 자료를 얼마나 따르는지는 실험으로 확인한다. 단계 2는 행동 확률과 실행을 연결하고, 단계 3은 온라인 가소성까지 포함하는 목표다. 작은 실험으로 끝내거나 장기 선호를 전부 프롬프트 문구로 대체하지 않는다. 다만 단계별 구현 PR은 실제 변경 시점의 코드·회로·검증 결과로 다시 구체화한다. 이 문서만으로 제품 활성화나 배포가 이뤄졌다고 보지 않는다.

최초 구현에서는 회로 명세의 정확한 세포 목록·경계 자극, 의미 특징 공간, 가소성 마스크와 학습 규칙을 확정해야 한다. 이후 조정은 하나의 버전에서 여러 설정을 동시에 바꾸지 않고 기록한다. 모델·회로·변환기 변경 시 기존 개인 상태의 이전 규칙도 함께 제공한다.

## 효용을 판정하는 방법

제품 전체의 효과와 초파리 배선의 기여를 따로 측정한다. 전자는 경험으로 바뀌는 선택, 개별성, 사용자가 느끼는 연속성, 운영 비용이다. 후자는 같은 입력·기억·학습·느린 상태·출력 크기에서 원래 회로가 만드는 추가 효과다. 이 둘을 혼동하면 좋은 제품을 만들고도 잘못된 과학적 설명을 붙일 수 있다.

비교군은 변조 없음, 독립 잡음, 맥락 의존 AR(1), 작은 일반 재귀망, 원래 초파리 회로, 차수·부호·가중치 분포를 가능한 한 보존한 재배선 회로다. 외부 학습만 있는 구성과 회로 내부 가소성이 있는 구성도 비교한다. 변조 평균·분산, 기준 정책에서 벗어난 정도, 시간 상관을 가능한 범위에서 맞춘다. 더 강하게 흔든 모델이 더 개성 있게 보이는 효과를 회로 우위로 셈하지 않는다.

처음에는 동일한 후보를 재생해 선택층의 차이를 측정하고, 다음에는 자유로운 후보 생성까지 포함한다. 조건 이름을 숨긴 실제 행동 이력 평가를 사용한다. 감정적인 문장과 에이전트의 자기 보고만으로 점수를 주지 않는다. 학습·조정 이력과 평가 이력은 분리하고, 8명 운영 시험 외에 독립 이력·시드 반복을 둔다.

Moirai 상태 전달은 원래 대화와 완결된 익명 조언을 고정하고 상태만 바꾼 비교도 둔다. 선택·제안·자발적인 활동 변화와 단순 말투 변화를 구분한다. 미수신·불완전 조언은 종합에서 제외하는 것으로 끝내지 않고 기존 계약대로 회차 종합을 중지한다. 신경 서비스만 실패했을 때의 무변조 경로와 구별한다. 일반 대화의 자연어 선택에서 추정한 빈도를 Host가 보장한 행동 추출 확률로 보고하지 않는다.

| 질문 | 필요한 검사 |
| --- | --- |
| 회로가 선택에 인과적으로 참여하는가 | 현재 입력·기억을 고정하고 신경 상태 교환·초기화, 입력 제거, 읽기 차단, 재배선 |
| 경험이 취향을 만들었는가 | 시드 교체 후 경향 유지, 반대 피드백 후 수정, 보상 연결을 섞은 대조군 |
| 순간 기분과 장기 취향이 다른가 | 빠른 상태·느린 상태·학습 가중치를 따로 초기화하고 지속 시간을 측정 |
| 실제 선택권인가 | 선택 ID와 실행 ID 일치, 보류 후 무실행, 무효화 사유와 새 결정 연결 |
| 실용적인가 | 품질·의도 보존, 전환 적절성, 개인별 일관성·차이, 지연·비용·복구 |

일반 반복망이나 상관 잡음이 더 좋은 부분에서는 해당 모듈을 교체할 수 있다. 부분회로에서 유용한 반응을 얻으면 학습 회로와 재귀 회로의 연결을 넓히고, 경계 자극에 지나치게 의존할 때는 더 넓은 회로를 검토한다. 전뇌는 이 확장 경로에 포함되지만, 전뇌라는 크기 자체를 제품 가치의 기준으로 삼지 않는다.

제품 지원 여부는 원하는 행동이 실제로 나타나고 품질·운영 예산을 충족하는지로 판단한다. 단순한 대안과 동등해도 조사 가능성·회로 조작·생물학적 출처가 주는 연구 가치로 별도 프로필을 유지할 수 있다. ‘초파리 배선이라 더 자연스럽다’는 주장은 그 차이를 입증한 결과가 있을 때만 쓴다.
