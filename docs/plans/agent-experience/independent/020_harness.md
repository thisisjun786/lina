## Audit amendment: parity and private evaluator boundary

NEW `scenario-export.ts` prepares separate public-case JSON and private-truth JSON. Evaluation subprocess alone reads private truth; runner takes only public-case path and emits allowlisted traces. Generator returns no combined object to runner. Public case contains opaque random episode ID unrelated to criterion/seed; mapping remains private. Tool catalogs/data are public environment capabilities, evaluator truths never imported by runtime. Independent negative test injects a unique evaluator canary into private fields and fails any appearance in serialized requests. Expected numeric answers may naturally occur in raw data; forbid hidden expected-answer fields/objects, not every coincident substring.

One `serializeInput` and common action-schema/system prompt for all modes, identical model params and raw-source cap. Identical-history fixture must serialize byte-identically after removing labeled derived block and host metadata. Kernel/ablation differ only on derived block consumption, baseline bypasses kernel adoption/currentness while retaining shared environment permissions. After different actions histories legitimately diverge: report first divergence; compare common raw source access, initial data, tools and per-request/episode budgets, never claim all subsequent requests are byte-identical. Derived text counts toward same total input cap. No hidden retries or mode-specific termination: answer/noop/defer or six attempts ends all modes.

`score.ts` computes exactly the predicates in 005_scoring_contract.md from private truth and actual outputs/effect ledger; semantic supplemental reviews do not contribute numeric score. Every invalid generated fixture is caught pre-dispatch and invalidates batch; model invalid output/timeout/limit failure scores zero. Provider unavailability marks qualification incomplete and retains attempts, not drops them for a higher denominator.
