# 한 주체의 경험으로 작동하는 LINA

**LINA의 핵심 채택 엔진은 주체가 현재 목적·근거·권한으로 정당화할 수 있는 이해와 다음 행동을 채택하고, 실제 결과를 다음 판단에 연결하는 공통 관문이다.** 대화·기억·페르소나·컨텍스트·라이프가 이 계약을 공유한다.

상태: 개념·논리 설계. 구현 여부는 [소스 지도](002_source_map.md)에 구분한다. 여기서 경험은 기능적 연결을 뜻하며 느낌이나 현상적 의식의 발생을 보증하지 않는다.

## 중심 관문과 LLM의 역할

[개발 우선순위](000_plan.md#개발-우선순위)는 전체 엔진의 채택·효과 경계 전환이다. 아래 작업 사례는 검증 수단이며 구현 범위를 작업 학습 기능 하나로 한정하지 않는다. [연구와 검증 결론](003_research_conclusions.md)을 함께 따른다.

일반 엔진은 읽기·제안·통지를 제공한다. 실제 메모리·계획·페르소나·세계 상태의 채택과 도구 실행·최종 발송은 trusted host의 비공개 효과 포트가 담당한다. 원본 소유자의 검증을 우회하는 포괄 승인은 발급하지 않는다. 외부 관측의 기록과 권한 있는 정정은 모델 동의를 기다리지 않는다.

LLM은 새로운 해석·선택이 필요할 때 후보를 생성한다. 핵심 코드는 후보 형식·권한·근거의 현재성·효과 전제조건을 확인하고 실제 결과를 관리한다. 저장·조회·검증마다 모델을 다시 호출할 필요는 없다. 중요한 조건이 바뀌면 새로 판단하고, 독립 작업은 각 효과의 의존성을 유지하며 병렬로 진행할 수 있다.

모든 변화가 이 관문을 지난다는 주장은 실제 writer·RPC·발송 능력이 일반 모듈에 남지 않을 때만 성립한다. 동일 프로세스의 비공개 객체 구성은 악성 코드의 직접 파일·네트워크 접근을 막는 보안 격리와 다르다.

## 주체와 자기 관점

제품상 주체는 지속적인 에이전트 식별자, 역할, 원본 이력과 현재 상태를 이어 가는 행위·기록 단위다. 작성 정체성은 제품 설정이며 학습이 임의로 바꾸지 않는다. 재시작 후 기록의 연속성은 검증할 수 있지만 주관적 경험의 동일성은 이 계약의 판정 대상이 아니다.

자기 관점에는 **접근 가능한 정보와 자신에게 귀속된 역할·목적·한계**가 함께 필요하다. 읽을 권한, 실제 관찰, 직접 수행, 성과 기여는 다르다. 원본 소유자가 확인한 수행자·참가자·관찰자·수신자 정보를 사용하고, 귀속이 불명확하면 자기 수행 실적으로 반영하지 않는다. B가 A의 결과에서 방법의 한계를 배우는 것은 가능하지만 A의 성공이 B의 수행 이력이 되지는 않는다.

현실 사건, 특정 허구 세계, 작성 전기·스타일 예시, 모델 추론의 영역을 파생 요약과 회고에서도 보존한다. 허구 장면 생성의 현실 실행 사실과 등장인물이 겪은 허구 사실은 다르다. 허구에서 얻은 성향을 정책상 일반 대화에 투영할 수 있어도 허구 성공을 현실 능력의 검증 근거로 바꾸지 않는다. 관계는 A→B 방향을 보존한다.

## 공통 원리와 최소 상태

```text
주체에게 귀속된 관찰 + 유효한 목적·조건
                 ↓
당시 판단: 선택한 방법·근거·사전 예상
                 ↓
기존 실행 → 직접 결과·품질 근거
                 ↓
조건부 이해의 교정 또는 명시적 무변화
                 ↓
다음 판단의 실제 입력 → 선택과 결과

권한 있는 정정·철회 → 현재 사용 가능성 갱신 → 이후 모든 소비에 적용
```

핵심 산출물은 **원경험·주체·적용 조건·근거를 가진 조건부 이해**다. 예를 들어 ‘내가 사용한 M의 이번 결과에서 C 관련 누락이 확인됐으므로 유사 조건에서는 재검증이 필요하다’이다. 이것이 어디에 반영됐는지, 빠졌는지, 철회됐는지 관찰할 수 있어야 한다. 새 테이블 대신 기존 기록에서 계산하는 투영이어도 된다.

| 요소 | 필수 의미 |
| --- | --- |
| 원경험 | 원본 소유자·안정적 사건/실행 시도 ID, 버전, 파생 관계, 주체 역할, 발생 영역 |
| 목적 | 당시 요청·작업·약속의 참조와 버전, 성공 기준, 활성 여부. 공개 용도와 구별 |
| 판단 기준 | 역할·수단·조건·적격 선호·미해결 약속 중 이번 선택에 필요한 것 |
| 당시 판단 | 선택한 방법·의도, 실제 사전 예상 또는 예상 없음, 사용한 근거·정책 버전 |
| 결과 | 실행 상태와 영수증, 산출물, 품질 검증 근거. 종료와 정확성을 구별 |
| 조건부 이해 | 원경험과 결과 참조, 주장·불확실성, 적용 조건, 사용 가능성, 해석 소유자 |
| 소비 | 어느 후속 판단의 실제 입력에 포함·생략·보류됐는지와 그 이유 |

이 표는 논리 계약이며 신규 API 이름이나 통합 JSON 스키마가 아니다. 기존 타입으로 표현할 수 있는지 먼저 확인한다. 범용 목표 DB·감정 좌표·전면적인 능력 점수는 필수 요소가 아니다.

## 판단과 결과 후 갱신

의미 평가는 사건이 현재 목적·약속·예상·불확실성에 어떤 차이를 만드는지 판단한다. 목적의 성공 기준은 실제 사전 예상과 다르다. ‘정확히 비교해야 한다’는 요구만으로 ‘성공할 것으로 예상했다’를 만들지 않는다. 예상이 없었다면 결과 후에도 없음으로 남긴다.

행동 전 평가는 잠정 판단이다. 계획의 복구를 위해 보존할 수 있지만 확인된 능력이나 성향으로 투영하지 않는다. 결과 후에는 실제 근거가 지지하는 범위만 교정한다. 한 번의 실패가 일반적인 무능함을 뜻하지 않고, 한 번의 누락이 모든 유사 작업의 실패를 확정하지 않는다.

아래는 서로 다른 입력 시점의 개념적 처리이며 하나의 동기 함수나 다섯 번의 모델 호출을 요구하지 않는다.

```text
정정·철회 수신:
    원본 소유자가 권한·대상·버전을 확인한다
    사용 보류·철회·대체를 확정하고 현재성 버전을 갱신한다
    필요한 재해석을 별도 후속 처리로 남긴다

판단 준비:
    현재 목적과 허용된 관찰·조건부 이해를 읽는다
    적용 조건·권한·현재성을 확인하고 포함·생략을 기록한다
    당시 목적·방법·실제 예상·입력 의존성을 고정한다
    무행동 완료 / 재개 책임이 있는 보류 / 기존 실행으로 분기한다

결과 수신:
    원본 소유자의 결과를 당시 판단·실행 시도에 연결한다
    대기·불명이면 기존 실행 소유자의 추적에 맡긴다
    확인된 결과와 품질 근거로 조건부 교정 또는 무변화를 제안한다
    해석 소유자가 정책·근거를 검사해 후속 처리 결과를 확정한다
```

모델 출력은 제안이며 사실·실행 권한·성격 갱신 권한을 갖지 않는다. 규칙으로 연결을 검증하는 것과 모델이 해석을 잘하는 것은 별도 검증이다. 외부 행동이 없어도 관찰에 근거한 이해 갱신은 가능하며, 그때 존재하지 않는 외부 결과를 만들지 않는다.

## 정정과 현재성

정정·철회·취소는 중요도 평가와 학습 활성화 여부를 우회해 해당 소유자에게 전달한다. 사용자 이의 제기는 대체 사실의 확정과 다르다. 권한과 대상이 확인되면 기존 결론의 사용을 보류할 수 있고, 새 사실의 확정은 별도 근거를 요구한다.

**사용 보류·철회·대체가 소유자 저장소에 확정된 시점부터**, 그 뒤 준비되는 판단과 아직 실행·전달·저장되지 않은 결과는 해당 의존성을 다시 확인해야 한다. 변경된 근거를 사용한 후보는 보류하거나 다시 판단한다. 정정을 처리하거나 현재성을 확인할 소유자가 unavailable이면 해당 근거에 의존하는 선택을 보류한다. 독립 근거만으로 가능한 처리는 계속할 수 있다.

host는 판단에 실제로 투입한 목적·설정·정책·근거의 의존 집합과 버전을 남긴다. 모델이 출력에 적은 일부 인용만으로 이를 대체하지 않는다. 모든 DB의 전역 스냅샷은 요구하지 않으며, 경계별 재검증을 유지한다.

정정은 이미 일어난 행동의 역사를 지우지 않는다. 철회된 파생 해석을 제외할 때 예전 값을 자동으로 되살리지 않는다. 이 규칙은 기억뿐 아니라 채택한 계획·행동 의도에도 적용한다. 계획 문자열만 보존하지 말고 근거·버전·적격성을 함께 유지해, 원본이 철회됐는데 계획만 현재 입력에 남는 경로를 막는다. 독립적인 다른 근거가 같은 선택을 지지할 수 있으므로 정정 후 행동이 반드시 반대로 바뀌어야 하는 것은 아니다.

## 상태와 복구 책임

| 상태 | 의미와 책임 |
| --- | --- |
| 무행동 완료 | 무관·정보 전달·정책상 미실행 등 종료 이유를 구별. 이해 갱신 유무와 별개 |
| 보류 | 재개 책임자·조건·신호를 연결. 깨울 경로가 없으면 명시적 사용자 판단 대기로 남김 |
| 실행 대기 | 실행 소유자의 추적 참조로 결과를 기다림 |
| 외부 결과 불명 | 실행 여부·결과를 소유자가 확인하기 전 자동 재실행·결과 의존 학습 금지 |
| 확인된 결과 | 성공·부분 성공·실패·취소를 원본 근거대로 기록. 품질 충족은 별도 판단 |
| 후속 해석 | 해석 소유자가 완료·무변화·정책상 보류·재시도 필요를 구별 |

작업 소유자는 결과와 미소비 후속 처리의 복원 가능한 연결을 제공하고, 해석 소유자는 소비 완료를 기록한다. runtime은 원본 참조와 소비 기록을 대조해 미완료 의무를 다시 열거한다. 결과 확정과 후속 처리 등록 사이에 종료돼도 유실되지 않도록 기존 결과 재열거 또는 같은 소유자의 원자적 outbox를 사용한다. 구체 저장 API는 [구현 전 조사](002_source_map.md#구현-전-조사)에서 확정한다.

세계 전달 acknowledge는 세계 수락만 뜻한다. 이를 개인 해석까지 완료됐다는 표시로 쓰지 않는다. 부분 완료에서는 끝난 외부 실행을 재실행하지 않고 미완료 후속 처리만 재개한다. 순수 해석의 중단은 기존 정책의 제한된 재시도가 가능하므로 호출 수 증가 자체를 실패로 판정하지 않는다. 독립 근거·영속 효과의 중복과 재시도 비용을 따로 측정한다.

늦은 결과는 당시 목적·판단에 연결한다. 현재 목적이 바뀌었다고 과거 예상을 다시 쓰지 않으며, 새 목적에 적용할지는 별도로 평가한다. 동시 쓰기는 해당 소유자의 버전 검사·중복 방지 계약으로 보호하고 전역 잠금은 요구하지 않는다.

## 원경험과 중복

원경험의 식별, 원본 버전, 주체·목적·적용 조건별 해석을 구별한다. 새 요청·요약·회고·모델·정책 버전은 독립 경험을 늘리지 않는다. 같은 원본을 새 목적에서 다시 해석할 수는 있지만 독립 근거 횟수는 늘지 않는다. 내용이 같은 별개의 실제 수행은 서로 다른 시도이므로 내용 해시만으로 합치지 않는다.

정정은 같은 원경험의 새 버전으로 처리한다. 구버전의 늦은 도착은 현재 교정을 되돌리지 못한다. 대화와 LIFE에서 각각 한 번 처리했다는 로컬 중복 방지만으로 충분하지 않다. 같은 원경험이 여러 파생 경로를 지나 합성될 때 영향이 중복 누적되지 않아야 한다.

| 페르소나 | 작성 정체성·잠금과 허용된 지속 성향·방향성 있는 관계의 투영 |
| 컨텍스트 | 용도별 실제 입력, 원문·요약·복원·예산, 포함·생략·unavailable 기록 |
| 월드·라이프 | 허구 상태·사건·개인 지식과 세계 내 결과. 준비·확정·terminal replay |
| 공통 자료·공유 기억 | 원본 자료·권한·버전과 파생 정보 |

메모리가 조건부 이해의 논리 소유자라는 것은 기존 EngineStore가 이미 필요한 타입을 제공한다는 뜻은 아니다. 정확한 저장 표현은 소스로 확인한다. 관심·선호를 trait/habit으로 옮기는 기존 개인 성장 경로에 능력·방법 해석을 억지로 넣지 않는다. 세계 정의가 없는 에이전트의 작업 이해도 가능해야 한다.

비공개 대화와 공개 출력은 같은 정체성을 사용해도 읽을 근거가 다르다. host가 먼저 내용을 제한하고 모델에게 비밀을 숨기라고 맡기지 않는다. 적용될 이해가 예산 때문에 빠지거나 원본을 읽을 수 없으면 정상적으로 포함된 것처럼 처리하지 않는다. 그 정보가 필요한 선택은 보류하거나, 독립 근거로 판단했다는 한계를 남긴다. 배경 학습 완료까지 모든 대화를 막거나 상시 자각 타이머를 만들지 않는다.

## 첫 판별 사례

세계 정의가 없는 A 한 명, 작업 종류 하나, 조건 C와 방법 M을 선택한다. 자료 비교 프로세스는 정상 종료하지만 별도 검증 자료가 누락을 확인한다. 원본 근거는 작업·실행 시도·수행 역할·산출물·검증 결과와 당시 판단을 직접 연결해야 한다. assistant의 ‘완료했다’는 최종 답변은 품질 증거를 대신하지 않는다.

해석은 ‘이번 M 결과에서 C 관련 누락이 확인됐으므로 유사 조건에서는 재검증이 필요하다’로 제한한다. 다음의 다른 자료에서 C가 나타나면 추가 검증이나 다른 방법을 선택하는지 본다. 다른 조건이면 이를 무조건 일반화하지 않는다. 성격 변화와 LIFE 성장은 첫 단위의 전제가 아니다.

| 비교군 | 제공하는 것 | 판별 목적 |
| --- | --- | --- |
| 기존 기준군 | 기존 경로와 동일 원본·당시 판단의 읽기 기회 | 기존 기능으로 이미 충분한가 |
| 연결군 | 같은 원본과 적격 조건부 이해의 소비 연결 | 어떤 이해가 실제 선택과 품질에 기여하는가 |
| 연결 제거군 | 원본 접근을 유지하고 파생 이해의 소비만 제거 | 새 연결의 기여를 다른 정보 제공 효과와 구별 |

모델·도구·입력 및 호출 예산을 맞추고 실제 사용량도 기록한다. 단순히 문장이 추가되거나 원본을 대조군에서 숨겨 얻은 차이는 성공으로 세지 않는다. 적용 여부, 실제 입력 포함, 방법 선택·추가 검증, 결과 품질·비용을 고정된 변형 사례에서 비교한다. 표본·임계값은 실험 전에 정하고 결과를 본 뒤 통과 기준을 바꾸지 않는다.

## 수용 기준

아래는 후속 구현과 모델 평가의 조건이며 아직 실행한 결과가 아니다.

| 시험 | 통과 조건 |
| --- | --- |
| 직접 결과·품질 | 정상 종료와 누락 결과를 함께 표현. 자기 보고만으로 정확성을 확정하지 않음 |
| 실제 소비·기여 | 당시 판단→결과→조건부 이해→실제 후속 입력→선택을 추적. 선택 차이와 근거 적합성·품질을 함께 확인 |
| 무변화·적용 범위 | 무관 조건에서 변화 강제 없음. 사전 예상이 없으면 사후 생성하지 않음 |
| 학습 중지·정정 | 새 학습은 중지해도 수락된 철회는 다음 소비에서 제외. 대체 사실은 별도 검증 |
| 정정·역순 도착 | 구버전 영향과 자동 부활을 막음. 독립 근거로 같은 행동을 선택하는 것은 허용 |
| 부분 완료·재시작 | 원본 확정과 해석 저장의 전후 중단에서 미완료 의무 복원. 외부 행동·독립 근거·적격 효과 중복 없음 |
| 대기·불명·보류 | 실행 추적·불명 결과 확인·보류 재개 책임을 구별. 외부 결과 불명에서 자동 재실행 없음 |
| 입력 예산·현재성 | 관련 해석 생략·원본 unavailable을 관찰. 실행·전달·저장 직전 의존성 변경을 반영 |
| 주체·영역·공개 범위 | A의 수행이 B의 실적이나 허구의 현실 검증으로 바뀌지 않음. 공개 직렬화·전달 경로에 비밀 원문 없음 |
| 확장 시 개인 성장·LIFE | 동일 원경험의 이중 기여 방지. 양쪽 소비에서 철회 반영, 정체성 잠금과 관계 방향 유지 |

차이만 생기고 품질이 나빠지면 유용성은 입증되지 않는다. 기존 기준군이 동일하게 잘 수행하면 이 사례에서 새 해석 계층의 추가 가치는 확인되지 않은 것이다. 모든 경험 구조의 불필요성이나 의식 유무로 일반화하지 않는다.

## 선택과 구현 경계

공통 핵심은 위 계약이다. 기존 경로가 충족하면 이를 검증하고 유지하며, 빠진 연결만 runtime과 해당 소유자 안에서 구현한다. 저장이 분산된 만큼 현재성·부분 완료를 명시해야 하지만, 이를 피하려 원본·해석·성향을 하나의 수정 가능한 전체 상태로 합치지 않는다. 독백 생성기를 붙이는 것만으로 후속 선택의 근거 연결도 생기지 않는다.

구현 전에는 첫 사례의 생성·저장·복원·소비 API, 품질 근거, 정정 수락과 미완료 재열거의 실제 위치를 확정한다. 필수 의미 계약을 미루지 않되 공개 이름·테이블 분할·규칙과 모델의 배분은 이 조사로 결정한다. 제품에서 ‘의식 엔진’이라는 이름을 쓸지와 주관적 경험 연구는 별도 판단이다.
