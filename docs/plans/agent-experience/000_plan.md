# LINA 최우선 개발 과제: 핵심 채택 엔진

**LINA의 개발 1순위는 대화·기억·컨텍스트·페르소나·작업·라이프의 채택과 효과를 관통하는 핵심 엔진이다.** 어떤 이해를 사용할지, 무엇을 실행할지, 그 결과를 어떻게 다음 판단에 반영할지를 하나의 계약으로 관리한다.

결정일: 2026-09-10. 제품 방향은 채택했고, 구현은 아직 완료하지 않았다. 이 문서가 개발 우선순위의 기준이다.

2026-09-10 실행 순서 변경: 사용자가 기존 LINA 엔진을 제외한 LLM·핵심 채택 엔진·최소 저장소/도구 연결의 [독립 실험](independent/000_plan.md)을 먼저 요청했다. 전체 전환에 앞서 30개 기준으로 기능과 한계를 평가한다. 기존 통합 설계는 후속 범위로 보존한다.

## 개발 우선순위

새 개발 작업은 먼저 이 엔진의 계약·통합·검증에 기여하는지 판단한다. 핵심 엔진에 직접 필요한 작업을 우선하고, 독립적인 UI·부가기능·엔진 확장은 뒤로 둔다. 후속 기능이 메모리 쓰기·계획 갱신·도구 실행·최종 발송을 새로 추가한다면 핵심 관문을 우회하는 경로를 만들지 않는다.

핵심 엔진을 연결하기 위한 선행 수정과 기존 기능의 장애·데이터 손상·보안 문제 복구는 필요한 범위에서 진행한다. 단순히 다른 기능이 구현하기 쉽다는 이유로 이 우선순위를 바꾸지 않는다. 제품 우선순위의 변경은 사용자의 명시적 지시로 남긴다. 이 결정은 진행 중인 다른 작업의 변경을 폐기하거나 프로세스를 중단하라는 지시가 아니다.

각 구현 계획에는 핵심 엔진에 대한 기여, 변경할 채택·효과 진입점, 남는 우회 경로와 검증 범위를 적는다. 문서 지침만으로 코드상 우회가 차단됐다고 주장하지 않는다.

## 채택한 중심 원리

> 관측은 원본 소유자에게 보존한다. 주체가 현재 목적·근거·권한으로 정당화할 수 있는 다음 단계를 채택하고, 실제 결과와 미해결 조건을 다음 판단으로 돌려보낸다.

상황별 if문이나 별도 성장 시나리오를 계속 추가하는 구조로 한정하지 않는다. 일반 엔진은 읽기·제안·통지를 제공하고, 실제 채택 상태의 쓰기·도구 실행·발송 능력은 trusted host와 효과 포트가 소유한다. 각 저장소는 원본과 로컬 불변 조건을 계속 소유한다.

LLM은 해석과 선택이 필요할 때 사용한다. 저장·조회·검증·정정 반영처럼 결정된 처리는 코드가 맡고, 중요한 조건이 바뀌거나 새 선택이 필요할 때 다시 모델에 묻는다. 같은 관문을 통과한다는 것이 모든 일을 직렬 실행하거나 매 단계 모델 호출을 한다는 뜻은 아니다. 독립 작업은 병렬로 진행하되 각 효과의 의존성과 현재성을 확인한다.

초기 주체·목적·정책·모델 능력·어댑터는 필요하다. 이 구조는 모든 의미적 판단의 정확성이나 현상적 의식을 보장하지 않는다.

## 우선 과제 완료 기준

- 채택 상태의 쓰기·도구 호출·최종 발송 경로를 열거하고 일반 엔진의 직접 실행 능력을 제거하거나 제한된 포트로 전환했다. 남은 예외는 원본 수집·권한 있는 정정 등 신뢰된 경로로 명시했다.
- 기억·계획·행동 의도 모두 근거와 적격성을 보존하며, 철회·역순 전달·동시 변경으로 부적격한 영향이 되살아나지 않는다.
- 실행 대기·불명·무행동·보류를 구별하고 실제 프로세스 재시작에서 의도·영수증·미완료 의무를 복원한다. 효과 중복과 재시도 비용을 따로 확인한다.
- 실제 모델 입력과 도구/발송 경계를 통과한 증거가 있으며, fixture 성공을 자연어 판단 품질이나 운영 내구성의 증거로 대체하지 않는다.
- 재판단 호출과 결정적 처리가 구별되고 독립 작업의 병렬성·입력/호출 비용이 확인됐다.

현재 상태는 설계와 독립 예시 검증이다. LINA 통합 완료, 배포, 주관적 경험의 발생을 선언하지 않는다. 커밋·PR·머지·배포는 해당 작업의 별도 승인 범위를 따른다.
