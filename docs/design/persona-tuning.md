# Persona Tuning: Onboarding Architecture

Status: adopted as the default specification (2026-09-26). The flow and item formats are decided. Item wording, axis ranges, and prompt tuning happen during product development.

This document describes how a user shapes the default persona to fit them, and how the same machinery creates a new persona. It is product design only. Character sheets, worldview, and persona text live in a private repository and are not part of this document.

## Goals

- Let each user set a comfortable starting point for how the persona talks and works, in a few minutes, without it feeling like a settings form or a generic personality test.
- Verify the choice through a real, live conversation rather than trusting a score.
- Reuse the same flow to create a new persona inside the same format and rules.

## Order of work

1. Define the tuning axes and their ranges (what can vary per user).
2. Finalize the default persona against those ranges: the core that never varies and the defaults.
3. Build new-persona creation as a feature inside that frame: same source format, same rules, with the user as author.

## Flow

1. **Introduction.** The persona introduces itself briefly and asks whether it may ask a few questions. Three choices: answer the questions, start right away with defaults, or create a new companion.
2. **Staged questionnaire** (all items skippable; about 13 items):

| Stage | Items | Formats | Sets |
|---|---|---|---|
| Relationship | 2 | pick one of four roles; A-or-B tradeoff | `role`, `focus` |
| Voice | 4 | two scenarios with live replies; length pick; free text | `warmth`, `play`, `length`, `address` |
| Work | 4 | two scenarios with live replies; two A-or-B tradeoffs | `initiative`, `pushback`, `autonomy`, `report` |
| Boundaries | 3 | pick; multi-select dislikes; free text | `memory`, `avoid[]`, `wish` |

3. **Result card.** A short type name (for example "warm, speaks up, colleague"), chips for the chosen axes, the preferred form of address, and what to avoid. The card is decoration; it is not treated as an accurate assessment.
4. **Live calibration.** A real conversation using the chosen settings, with one-tap adjustments: warmer, plainer, shorter, longer, and "talk like this" (free text). An adjustment regenerates the last reply.

New-persona creation asks for a name first, then runs the same stages with the new name, then the same calibration.

## Item formats

- **Scenario items (situational judgment).** Show a concrete moment and a user message. Each option is a *live reply generated by the model* under that option's rule, shown side by side. Choices made earlier are applied to later previews, so the persona takes shape as the user answers.
- **Tradeoffs (forced choice).** Two good options, pick one. Removes the "agree with everything" problem.
- **Agree/disagree items, used selectively.** They are intuitive, so some types keep them. Use them only for statements that split people (habits and tastes such as "I rarely read long replies to the end"), never for statements everyone agrees with, and mix reverse-keyed statements. Placement and count are decided during tuning.
- **Free text** for address and personal requests.

## Axes

| Axis | Low end | High end | Model distinguishes it? |
|---|---|---|---|
| warmth | brief acknowledgment, then practical | receives feelings first, stays close | yes |
| play | calm, serious | occasional light humor | yes |
| length | at most two sentences, no lists | detailed, structured when needed | weak unless expressed as a sentence cap |
| initiative | answers only what is asked | points out a few preparations proactively | yes |
| pushback | follows the user's decision | states disagreement once, then follows | yes, but runs against sycophancy bias |
| autonomy | confirms direction first | does small reversible work first, reports after | untested without tools |
| report | result only | what and why | not measured |
| memory | work facts only | remembers personal details and follows up | depends on memory system |

Rules are written as observable behavior ("at most two sentences"), not adjectives ("concise"). With adjectives only, generated replies for different warmth levels were nearly identical.

## Data

Per-user settings live in a user layer, separate from the persona source written by its author:

```
userVoice {
  axes: { warmth, play, length, initiative, pushback, autonomy, report, memory: -2..2 | null }
  role, focus
  address?: string
  avoid: string[]
  wish?: string
  adjustments: [{ label, rule, at }]
  decidedBy: "user"
}
```

Skipped axes stay `null`; later events or automatic growth may fill them. Prompt assembly order: persona core, persona default voice, `userVoice`, then learned growth. Adjustments are saved, survive restarts, and can be reverted.

## Invariants

- Settings change expression only. Facts, judgment, corrections of wrong premises, uncertainty, safety rules, and permissions are identical at every setting.
- No clinging, guilt, or isolation, regardless of warmth.
- Low pushback never suppresses safety concerns. Low autonomy is the default for anything irreversible; irreversible actions always require confirmation.
- Everything is skippable, and nothing is forced before first use.
- On-screen text never uses words like "evaluation", "score", or "configuration value".

## Evidence summary

- Agree scales invite acquiescence, which distorts results (Rammstedt & Farmer 2013, https://doi.org/10.1037/a0033323). Forced choice reduces response bias and faking (Brown & Maydeu-Olivares 2011, https://doi.org/10.1177/0013164410375112; Cao & Drasgow 2019, https://doi.org/10.1037/apl0000414).
- Scenario items with "what would you do" instructions align with personality preferences (McDaniel et al. 2007, https://doi.org/10.1111/j.1744-6570.2007.00065.x).
- One or two items per dimension are too unstable to judge an individual (Mini-IPIP, https://doi.org/10.1037/1040-3590.18.2.192); hence no scoring, only live verification.
- Type labels feel accurate even when generic (Forer 1949, Barnum effect), so the card is not the source of truth.
- LLMs express prompted traits distinguishably (https://arxiv.org/abs/2307.00184), but they drift over turns (https://arxiv.org/abs/2402.10962), default to agreement (https://arxiv.org/abs/2310.13548), and default to long answers (https://arxiv.org/abs/2404.04475).
- Warmth tuning can raise sycophancy; OpenAI rolled back a GPT-4o update for this reason (https://openai.com/index/sycophancy-in-gpt-4o/).
- Products commonly offer preset plus optional depth, and show example replies or previews (ChatGPT personalities, Claude styles, Gemini Gems preview, Sesame agent previews).

## Prototype findings

A private prototype ran this flow end to end on desktop and mobile widths with a live model.

- Warmth, initiative, humor, and pushback produced clearly different replies at their two ends.
- Length needed an explicit sentence cap.
- A "no comfort phrases" rule still leaked comfort phrases, so rules that fight the model's defaults need banned-phrase lists or example replies.
- Earlier choices visibly carried into later scenario previews.
- Not yet measured: completion time, user judgment of fit, and whether settings hold over many turns.

## Deferred tuning

- Pairwise calibration in conversation: occasionally show the current reply beside a one-axis variant.
- Branching: ask work items first for assistant-leaning users, voice items first for friend-leaning users.
- Scenario bank: two or three scenarios per axis, one sampled per run.
- Drift regression: check that settings hold after ten turns.
