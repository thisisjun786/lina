# LINA Working Rules

Follow [MANIFESTO.md](MANIFESTO.md) for product principles and [CONTRIBUTING.md](CONTRIBUTING.md) for the contribution process. The user's latest explicit instructions take precedence.
Product design contracts live in [docs/design](docs/design/); implement against them and change them by PR.

- Read the requested scope and relevant files before making changes. Keep changes focused.
- Follow the [language policy](CONTRIBUTING.md#language) for issue and PR titles and bodies.
- Branch from `dev` and target `dev` with PRs. Use merge commits. Only the owner-authorized release workflow advances `main`.
- Preserve other contributors' work, branches, and worktrees.
- Verify changes and report what was and was not checked. Do not write tests that pin prose or pass by timing luck.
- Keep secrets, personal conversations, memories, user files, and operational state out of the repository.
- Obtain explicit authorization before opening PRs, merging, releasing, or deploying.
- Clean up temporary processes and resources created for the task.
